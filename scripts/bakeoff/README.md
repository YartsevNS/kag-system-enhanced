# Инструменты замеров OCR и таблиц (bake-off)

Здесь лежат скрипты, которыми мы получали ЦИФРЫ, опубликованные в
`docs/guides/table-structure-bakeoff.md`. Раньше они жили только в игнорируемом каталоге `reports/_scratch`
и могли быть потеряны вместе с рабочей копией. Перед сменой железа они зафиксированы здесь, чтобы
перезамер на новом CPU делался ТЕМИ ЖЕ инструментами, а не заново написанными.

## Железо, на котором получены цифры (важно!)

Intel Xeon E5-2682 v4 (Broadwell, 2016): **AVX2 есть, AVX-512 / VNNI / AMX — НЕТ**; 20 ядер на 41, 4 на 18.
Все выводы ниже **условны для этого CPU**. На новом железе обязательно перепроверить:

| Что проверяли | Вердикт на Broadwell | Почему на новом CPU может стать иначе |
|---|---|---|
| INT8 распознавателя (dynamic, per-channel) | отклонён: 3–4,5× медленнее, 1407 подстановок цифр | нет VNNI → INT8 эмулируется; с VNNI/AMX он обычно ускоряет, но подстановки цифр проверять всё равно обязательно |
| Батч ячеек (48×320, фиксированный размер) | отклонён: 3,02 с против 1,71 с у поштучных | на новом CPU с большим кэшем/каналами батч может выиграть |
| OpenVINO EP, FP32 | принят: 1,6–2,35×, цифры идентичны | выигрыш обычно больше при AVX-512; перемерить и зафиксировать |
| INT8 детектора таблиц | не ускоряет (0,67 → 1,32 с), но жмёт модель 127,5 → 35,2 МБ | с VNNI может стать быстрее FP32 — перемерить IoU и время |

Базовые цифры для сравнения (те же страницы, те же метрики):

```
накладная-скан (292 строки, 284 числа):  FP32 CPU 4,6 с | OpenVINO 2,0 с | INT8 15,7 с (1407 подстановок)
смета-скан (60 строк, 31 число):         FP32 CPU 2,4 с | OpenVINO 1,2 с | INT8 5,9 с
через API службы 41:                     накладная 3,6 → 2,2 с | смета 3,1 → 1,5 с

наш grid:                                смета 8×3 качество 0,98 | конспект 38×3 (переразбиение абзацев)
```

## Протокол замера (одинаков для всех кандидатов)

1. **Числа:** нормализация (пробелы-разделители убираем, запятая → точка, валюта отбрасывается),
   эталон — текстовый слой PDF или ручная разметка; считаем precision / recall и **подстановки цифр**
   (6↔8, 0↔6, 5↔3) — отдельным вердиктом «цифры не поехали».
2. **Арифметика:** строка верна, если выполняется `a × b ≈ c` (допуск 2 %). Это не фильтр, а разметка
   ролей колонок — количество / цена / сумма — без чтения шапки.
3. **Структура:** строк и колонок против истины, шапка — посимвольно.
4. **Время:** секунды на страницу (LLM-шаги конвейера в замер не входят).

## Скрипты: где и как запускать

Все замеры на модельном сервере делаются в отдельном venv `/home/yartsevn/table-bakeoff/.venv`
(там rapidocr, rapid_table, onnxruntime-openvino). Страницы-образцы — `/home/yartsevn/table-bakeoff/img/`.

### Замеры инференса (сервер 41)

| Скрипт | Что делает |
|---|---|
| `int8_hypothesis.py` | предметный тест INT8 распознавателя: режимы `int8_all`, `int8_head_fp32`, `backward`; время + подстановки цифр |
| `openvino_and_batch.py` | CPU EP против OpenVINO EP на реальных вырезках строк; поштучно против одного батча |
| `openvino_rapidocr.py` | полный пайплайн страницы: подмена провайдера в rapidocr без правки препроцессинга/декодера |
| `detector_probe.py` | первый пробник детектора области таблицы: контракт модели, боксы, время |
| `detector_speed.py` | детектор FP32 против INT8 (IoU, ложные срабатывания, размер, время), плюс OpenVINO EP |
| `slanet_inventory.py` | что лежит в `rapid_table` (пути, размеры, sha256) + тест селектора numeric/prose |
| `slanet_on_crop.py` | SLANet-plus на кропе от нашего детектора против полной страницы |
| `selector_region.py` | признак numeric/prose по всей странице против области таблицы |
| `route_calibrate.py` | калибровка поколоночного признака (печатает доли чисел по столбцам) |
| `measure_service.py` | замер службы OCR через её HTTP API (`/ocr` принимает СЫРЫЕ PNG-байты, не JSON) |

### Служба OCR на 41

| Файл | Что делает |
|---|---|
| `patch_ocr_service_openvino.py` | добавляет службе флаг `--engine cpu\|openvino` (идемпотентно, делает копию `ocr_service.py.orig-cpu`) |
| `openvino-service.sh` | управление копией службы на 8021: `start / stop / restart / status / check` |

### Стенд 18 (через контейнеры)

| Скрипт | Что делает |
|---|---|
| `reprocess_doc.py` | запустить повторную обработку документа штатным API (пароль берётся из окружения контейнера) |
| `set_ocr_settings.py` | сменить настройки категории `ocr` через config_store с проверкой записи и чтения обратно |
| `set_ocr_url.py` | сменить только адрес службы OCR (то же с проверкой) |

## Как воспроизвести замер (пример)

```bash
# на 41
cd /home/yartsevn/table-bakeoff && .venv/bin/python openvino_and_batch.py
cd /home/yartsevn/table-bakeoff && .venv/bin/python slanet_on_crop.py

# на 18: замер через живую службу и полный путь документа
scp scripts/bakeoff/measure_service.py 18:/tmp/
ssh 18 'docker cp /tmp/reprocess_doc.py kag-api:/tmp/ && docker exec kag-api python /tmp/reprocess_doc.py <document_id>'
ssh 18 'docker logs --since 3m kag-system_worker_1 | grep -E "восстановлено таблиц|parse \("'
```

## Чего этими скриптами НЕ проверено

- Поведение под нагрузкой: воркер стенда работает `--pool=solo`, то есть документы идут строго по одному,
  параллельной очереди к службе OCR сейчас нет (балансировка двух портов поэтому не делалась).
- Прозаические таблицы (конспект, истина 4×3): ни наш grid, ни SLANet не дают логических строк —
  нужен детектор безлинейных ячеек (`RT-DETR-L_wireless_table_cell_det`) и склейка строк внутри ячейки
  (склейка реализована в `src/indexing/table_type_route.py`, модель — нет).
