Числа считаются внутри api из тех же метрик, что отдаются в Prometheus (/metrics) — Grafana не нужна. Каждый запрос имеет trace_id: возьмите его из заголовка ответа X-Trace-ID и найдите в журнале (Логи).
Стадии ответа: куда уходит время
Если стадия «модель» занимает 80–90% времени — оптимизировать поиск бессмысленно, рычаг в модели (кэш префикса, меньшая модель для простых вопросов, стриминг).
Ответы: сколько и какие
«Отказ без данных» — модель честно сказала «не найдено» при пустом контексте. Растущая доля отказов при растущем корпусе — сигнал к разбору поиска (домен, порог, чанкинг).
Отбор контекста и реранкер
Порог отсечения убирает посторонние фрагменты из промпта (дешевле и точнее). Реранкер полезен, только если реально меняет лучший фрагмент: доля изменений ниже 5% означает, что он тратит время впустую.
Модель: вызовы и токены (стоимость)
Промпт — это контекст, он оплачивается каждый раз. Сокращать его надёжнее, чем менять модель: отсечение уже дало −22% промпта.
Оценки пользователей
Оценка пишется вместе с trace_id в data/feedback.jsonl — по «плохо» виден весь путь запроса (поиск, отсечение, модель), без догадок.
