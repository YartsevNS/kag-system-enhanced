Справка: промпты, типы документов и маркеры

Как устроена настройка LLM-функций в KAG, какие типы документов и домены запросов существуют, и где их править.

1. Как настраиваются промпты

Каждая LLM-функция имеет свой системный промпт. Настройка — в админке: «Привязка функций к провайдерам» → поле «Системный промпт» для нужной функции.

Дефолтные промпты хранятся в prompts/*.txt (в git, не теряются при backup):

ФункцияФайлЧто делает
Чатprompts/chat.txtRAG-ответы: приоритет Qdrant/Neo4j, цитирование источников, стиль
Граф знанийprompts/graph.txtПравила извлечения сущностей и связей (Neo4j)
Анализ документовprompts/doc_analysis.txtКлассификация типа + title/summary/topics
Анализ запросовprompts/query_analysis.txtМаршрутизация вопроса по доменам (выбор схемы)

Если промпт в админке не задан — берётся дефолт из prompts/*.txt. Если задан — он переопределяет дефолт.

2. Актуальные системные промпты

Подгружаются автоматически из настроек (с дефолтами из prompts/*.txt).

3. Типы документов (классификация)

Типы задаются в админке → «Типы документов» (GET/POST /admin/models/doc-types). В промпт анализа документов подставляется актуальный список через плейсхолдер {type_labels}.

4. Маркеры определения типа

Классификация идёт двумя путями:

  • Регекс-эвристика (мгновенно, без LLM) — src/indexing/auto_tagger.py: правила по ключевым словам в имени файла и первых строках.
  • LLM-анализ (doc_analysis.txt) — маркеры по имени файла и содержанию, если эвристика не определила тип.

Маркеры (по имени файла):

ТипКлючевые слова в имени файла
invoiceсчёт, invoice, payment
contractдоговор, contract, agreement
reportотчёт, report, analytics
letterписьмо, letter
formформа, анкета, questionnaire
identityпаспорт, passport, удостовер
medicalмедицин, больнич, анализ
legalдоверенность, иск, суд
financialфинанс, bank, кредит
certificateсвидетельство, сертификат, certificate

policyрегламент, политик, инструкция
standardстандарт, гост, snip, iso

Полные маркеры по содержанию — в prompts/doc_analysis.txt (секция «ПО СОДЕРЖАНИЮ»).

5. Домены запросов (маршрутизация)

6. Нужны ли примеры (few-shot)

ФункцияПримеры нужны?Почему
Граф знаний (Neo4j)❌ НетJSON-формат задаётся инлайн; system_prompt >2000 симв. заменяется на дефолт
Анализ документов❌ НетМаркеры работают лучше few-shot
Анализ запросов✅ ДаМаленькая модель (qwen2.5:1.5b), примеры удерживают формат «одно слово»
Чат❌ НетПравила + формат контекста достаточны

7. Ограничения

  • graph.txt: если системный промпт длиннее 2000 символов — entity_extractor заменяет его на короткий дефолт (entity_extractor.py:_call_llm). Не раздувай промпт графа.
  • Обрезка эмбеддинга: текст чанка режется до 500 символов перед векторизацией (llm/embeddings.py, лимит GigaChat ~512 токенов).
  • {type_labels}: плейсхолдер в doc_analysis.txt заменяется актуальным списком типов из админки автоматически.
