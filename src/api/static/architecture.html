Как это работает

Конвейер обработки документа

  • • Текстовый слой PDF → PyMuPDF (мгновенно, без OCR)
  • • Скан → рендер 200 dpi → OCR строк (служба PP-OCRv5, иначе локальный движок)
  • • Таблицы: своя сетка по линиям → детектор области (второй шанс) → детектор ячеек для прозаических
  • • Чанки → векторы (Qdrant) → табличный слой (Postgres JSONB) → граф (Neo4j)
  • • Попутно: поисковый PDF со слоем текста, карточка документа, миниатюра

Почему решения именно такие (замеры)

  • • Железо Broadwell (2016): есть AVX2, нет AVX-512 и VNNI
  • • INT8 распознавателя отклонён: 3–4,5× медленнее и 1407 подстановок цифр
  • • OpenVINO принят: 1,6–2,35× без изменения цифр
  • • Батч ячеек отклонён на этом железе: 3,02 с против 1,71 с у поштучных
  • • Числовые таблицы — наша сетка (27×20), прозаические — детектор ячеек (конспект 38 строк → 5)

Контур поставки

  • • Закрытый контур: интернет у заказчика может отсутствовать
  • • Веса вшиты в образ; проверка офлайн (HF_HUB_OFFLINE=1) в приёмке
  • • Рантайм: onnxruntime + OpenVINO EP, cv2, PyMuPDF; без torch и PaddlePaddle
  • • Лицензии: PP-OCRv5, SLANet-plus, RT-DETR, PP-DocLayout — Apache-2.0
  • • Откат на прежний OCR — офлайн-архив образов 2026.09.27
