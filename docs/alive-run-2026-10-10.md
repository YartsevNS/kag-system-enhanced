## 4. Граф с новыми наработками

Граф при обработке был ВЫКЛЮЧЕН настройкой. Включён (`POST /admin/models/graph-build-config {"skip": false}`),
затем проверено построение по документам:

* фрагментов в графе: 10 933 → **10 954** (+21 = ровно фрагменты трёх новых документов);
* сущностей 36 991 → **37 102**; связей 134 994 → **135 341**;
* на узлах новых документов лежат наши поля версий: `schema_version` (версия словаря) и
  `extractor_version` (отпечаток промпта извлечения) — то есть переработка «что переразмечать при смене
  словаря» работает.

Замечание про мой промах: первая команда перестроения ушла с укороченными id (`ca8b000d`) и обработала
0 документов — в отчёт это попало как «0/0», потому что я не проверил результат по числам до конца.
Полные id и построение по ним дали +21 фрагмент.

**Стоимость графа для всего корпуса не запускалась.** Замер из кода: 136 из 147 секунд обработки
документа в 13 фрагментов — это граф. На 328 документах (10,9 тыс. фрагментов) это порядка 10+ часов
работы воркера и оплата LLM-токенов на каждый фрагмент. Решение о полном перестроении — за владельцем:
сначала предлагаю замерить один документ с хронометражем по этапам и посчитать цену всего корпуса.

**Важно для понимания состояния:** настройка построения графа при обработке теперь ОСТАВЛЕНА ВКЛЮЧЁННОЙ
(`system:graph.skip = false`). Это значит, что каждый новый документ теперь строится вместе с графом, и
это дороже по токенам, чем было. Если нужен экономный режим — вернуть `skip = true` (граф тогда строится
только кнопкой «Перестроить граф» на /kg или у отдельного документа).

## 5. Скачивание с сайтов по ИБ — перепроверено с паузой 2 секунды

Проба 12 встроенных источников (пауза 2 с между запросами, ещё 2 с перед перелистыванием страниц):

| Источник | Код | Найдено |
|---|---|---|
| **ГОСТ Р — Информационная безопасность** (gost.ru) | 200 | **116 ссылок** |
| **ЦБ РФ — акты по ИБ** (cbr.ru/information_security/acts/) | 200 | **7 ссылок**; пагинация стр. 2 — 200, 6 ссылок |
| ФСБ России — НПА | 200 | 159 ссылок `.htm`, **прямых файлов 0** — страница навигационная |
| Портал правовой информации (RSS) | 200 | лента живая |
| ЦБ РФ — нормативные акты (RSS) | **404** → исправлено | новый адрес `/rss/RssNews`: 200, RSS, 100 записей |
| ФНС России — письма (RSS) | **404** → исправлено | новый адрес `/rn77/rss/`: 200, XML |
| ФСТЭК России — документы | **отказ TLS** | сертификат выпущен «Russian Trusted Sub CA» (Минцифры) |
| SecurityNews (5 лент) | таймаут 30 с | сайт недоступен со стенда |

Что исправлено в коде по факту замера: ЦБ RSS → `https://www.cbr.ru/rss/RssNews`, ФНС RSS →
`https://www.nalog.gov.ru/rn77/rss/` (оба проверены пробой).

Что осталось с диагнозом:
* **ФСТЭК** — проверка сертификата падает «unable to get local issuer certificate»: в образе хранилище
  Debian (150 сертификатов) без российских корней Минцифры, и нет даже `update-ca-certificates`.
  Лечение: добавить в образ российские корневые/промежуточные сертификаты и ставить `ca-certificates`.
  Тест этого лечения не выполнен: команда с внешней загрузкой сертификатов **заблокирована** (требует
  подтверждения владельца, а его не было) — повторять не стал.
* **ФСБ** — источника в текущем виде нет: страница отдаёт только навигацию (159 `.htm`), файлы лежат на
  подстраницах. Нужен проход по подстраницам (отдельная небольшая доработка) либо отключение источника.
* **SecurityNews** — со стенда недоступен (таймауты); либо блокировка по ip, либо сайт лежит.

## 7. Приборы (как повторить)

```
docker cp <прибор>.py kag-api:/tmp/ && docker exec kag-api python /tmp/<прибор>.py …
```

* `scripts/bakeoff/stand_inventory.py` — состояние стенда: документы, коллекции, граф, настройки, очереди;
* `scripts/bakeoff/stand_orphan_files.py` / `stand_orphans_detail.py` / `stand_orphans_plan.py` —
  файлы без записей: список, содержимое мелких, разбор по SHA-256 (новые / дубликаты / карточки);
* `scripts/bakeoff/ocr_service_probe.py` — замер OCR на реальных страницах (время, строки, кириллица);
* `scripts/bakeoff/alive_run_new_files.py` — боевая заливка и обработка с ожиданием конечного статуса;
* `scripts/bakeoff/graph_build_probe.py`, `graph_verify_docs.py` — включение графа, прирост узлов,
  проверка полей версий по документам;
* `scripts/bakeoff/sources_probe.py` — проба источников с паузой 2 с; `sources_fix_probe.py` — подбор
  рабочих адресов для мёртвых;
* `scripts/bakeoff/ca_probe.py` — проверка доступа к сайту с российским корнем в комплекте;
* `scripts/bakeoff/processing_times.py` — фактическое время обработки документов.
