# Требования: разрешение сущностей и предел сжатия

Требование — проверяемое утверждение. Формат «дано / когда / тогда», с конкретными значениями.

Базовый объект для всех требований: документ `fb4d9a84-e723-41fa-970d-2ed75683674d`
(fstek-2014-mery-zashchity-gis.pdf), прогон Bronze `f16b25c3`, 321 фрагмент,
модель deepseek-v4-flash, `prompt_version` 13.

## R1. Невалидный ключ требования не попадает в TypeDB

**Дано:** в Bronze 508 строк `security_requirement`; 468 из них с пустым clause; среди
`requirement-id` есть голые числа («5» — 7 строк, «6» — 6, «7» — 5, «4» — 4, «8» — 3,
«3» — 3) и слова («пользователи», «аутентификац»).
**Когда:** выполняется разрешение сущностей по правилам 1a/1b.
**Тогда:** запись, чей ключ не проходит валидацию формата или не выводится из пункта чанка,
получает статус «в очереди разбора» и не создаёт объект в TypeDB; в очереди видна причина.

**Как проверить:** запрос к очереди разбора и к TypeDB:
`SELECT reason, count(*) FROM bronze_queue WHERE run_id='<run>' GROUP BY reason`
и сравнение числа принятых объектов с числом строк, прошедших валидацию.

## R2. Коллизии ключей не сливаются

**Дано:** 41 кластер `security_requirement` содержит более одной строки; в 33 из них описания
разные (пример: ключ «…|5» — 7 строк, 7 разных описаний).
**Когда:** выполняется conflict guard (правило 2a).
**Тогда:** кластеров, где ключ совпал, а описания несовместимы, — 0; каждая такая запись
в очереди с причиной «конфликт описаний»; сливаются только строки с совпадающими
структурными идентификаторами в описаниях.

**Как проверить:** повторный расчёт кластеров: число кластеров с более чем одной строкой,
у которых множества структурных идентификаторов в описаниях расходятся, равно 0.

## R3. Пункт чанка заполнен и записан в Bronze

**Дано:** clause пуст у 468 из 508 строк требований (92%).
**Когда:** повторный прогон или пересчёт на сохранённом прогоне с включённым заполнением
пункта.
**Тогда:** доля строк с непустым clause — не ниже 95%; для чанка, начинающегося с номера
пункта, clause равен этому номеру.

**Как проверить:** `SELECT count(*) FILTER (WHERE coalesce(clause,'')='') , count(*) FROM
extraction_bronze WHERE run_id='<run>' AND type='security_requirement'`.

## R4. Регулятор сводится к одному объекту по коду органа

**Дано:** 305 строк регулятора → 2 кластера: «фстэк россии» (304 строки) и «федеральная служба
по техническому и экспортному контролю (фстэк россии» (1 строка).
**Когда:** выполняется правило 3 через `issuers.canonical`.
**Тогда:** регулятор — 1 кластер; разные ведомства не слиты (у них разные коды: `fstek`,
`mincifry`, `cbr` …).

**Как проверить:** пересчёт кластеров регулятора: 1 кластер; дополнительно — вывод
`issuers.canonical` для контрольных названий, где короткое и полное имя одного органа
дают один код, а разные органы — разные коды.

## R5. Пересчёт идемпотентен и не требует новых прогонов модели

**Дано:** Bronze хранит сырьё прогона `f16b25c3`.
**Когда:** разрешение пересчитывается дважды подряд без нового прогона извлечения.
**Тогда:** оба расчёта дают одинаковые числа кластеров, очереди и принятых объектов;
новых обращений к модели — 0.

**Как проверить:** два запуска подряд, сравнение чисел; счётчик вызовов LLM до и после.

## R6. Результат сжатия измерен и записан

**Дано:** до правил — 2183 строки сущностей → 752 кластера (сжатие 2,9×); требования
508 → 450; меры 367 → 113; элементы 393 → 185; регулятор 305 → 2.
**Когда:** правила 1a/1b/2a/3 применены.
**Тогда:** в журнале и в `result.md` записаны числа до/после по каждому типу и число записей
в очереди по причинам; вывод «предел сжатия» подтверждён или опровергнут этими числами.

**Как проверить:** отчёт пересчёта на том же прогоне; сравнение с числами выше.

## Ограничения

- Не трогать базу `cybersecurity_ontology` (путь отката) и ветку `PREPROD`.
- Не удалять строки Bronze и записи очереди: только статусы.
- Не применять fuzzy к структурированным ключам (номера пунктов, коды мер).
- Не запускать повторную обработку документов (5+) без разрешения владельца.
- Промпт не менять в рамках этой работы: сначала разрешение, потом новые версии промпта.
