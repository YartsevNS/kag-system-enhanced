# Страница онтологии = живое отражение базы

## Что было не так

Страница /ontology читала схему один раз при открытии. Схему меняли не только через страницу,
но и скриптами и прямыми запросами к TypeDB. Результат: на экране один набор типов, в базе
другой, а журнал версий молчит — потому что правка прошла мимо API.

Проверка на стенде до правки:

    GET /api/v1/ontology/schema    → 11 сущностей, отпечатка нет, кеш не отключён
    журнал версий                  → последняя запись 06.11.2026, ntypes=67
    фактическая база (MCP)         → 11 сущностей + document_version и связи версий
                                     (появились 07.11 при ADR-008, в журнале не отражены)

То есть данные не «разъезжались» в API — их никто не сверял с журналом и не перечитывал
после внешней правки.

## Что сделано

1. `ontology_service.fingerprint(schema)` — отпечаток структуры (16 hex) по типам, owns,
   plays и ролям. Форматирование и порядок списков на отпечаток не влияют: меняется только
   структура.
2. `GET /api/v1/ontology/schema` теперь отдаёт `fingerprint` и `read_at` и запрещает кеш
   (`Cache-Control: no-store`).
3. `ontology_versions.note_external_if_changed(schema)` — при каждом чтении сверяет схему
   с последним снимком журнала. Разошлись — пишет запись `action="external"` с перечнем:
   что добавлено, что удалено, какие owns/plays появились. Совпали — ничего не пишет.
4. Страница /ontology: показывает время чтения и отпечаток, имеет кнопку «Обновить схему»,
   раз в 15 секунд и при возврате на вкладку сверяет отпечаток; при расхождении перерисовывает
   граф и список типов и пишет «Схема в базе изменилась — страница обновлена».
5. В журнале появились понятные подписи: «изменено вне UI», «исходное состояние».
