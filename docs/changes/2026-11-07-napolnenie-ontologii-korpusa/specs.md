# Требования: наполнение онтологии корпуса

## R1. Объекты из всех уникальных документов корпуса попадают в базу

**Дано:** в Postgres на 192.168.50.18 таблица `documents`: 137 записей не-новостей, из них
96 уникальных имён файлов, 95 в статусе `completed`, суммарно 6830 чанков.
**Когда:** выполняется массовое наполнение.
**Тогда:** в `cybersecurity_ontology_v2` не менее 5000 объектов; объектов с `source-chunk-id`,
которых нет среди чанков Qdrant, — 0.

**Как проверить:**
```
mcp__typedb_ro__query(database="cybersecurity_ontology_v2",
  query="match $x isa structural_element; reduce $c = count;")
```
и сверка `source-chunk-id` с `chunk_id` из коллекции `kag_documents`.

## R2. Повторный прогон не создаёт дублей

**Дано:** документ уже обработан, его объекты в базе.
**Когда:** запускается обработка того же документа повторно.
**Тогда:** число объектов до и после совпадает.

**Как проверить:** замер счётчиков по каждому типу до и после обработки одного документа.

## R3. У каждого объекта есть провенанс

**Дано:** объект записан в базу.
**Когда:** читаем его атрибуты.
**Тогда:** `source-chunk-id` заполнен и указывает на существующий `chunk_id` в Qdrant.

**Как проверить:** выборка 20 случайных объектов, для каждого — проверка `chunk_id` в Qdrant
через `/collections/kag_documents/points/scroll`.

## R4. Дубли документов не обрабатываются дважды

**Дано:** `r-1323565.1.pdf` имеет 34 записи в `documents`, `r-50.1.pdf` и `gost-r-34.pdf` — по 5.
**Когда:** формируется список на обработку.
**Тогда:** в списке 95 документов, каждая уникальная пара «имя файла + хэш содержимого» — один раз.

**Как проверить:** длина списка = 95; повторяющихся хэшей нет.

## R5. Ошибки не прерывают прогон

**Дано:** на одном из документов модель вернула невалидный ответ.
**Когда:** прогон продолжается.
**Тогда:** документ помечен как ошибочный в отчёте, остальные обработаны, итоговый отчёт содержит
число ошибок.

**Как проверить:** поле `errors` в итоговом отчёте; при нуле ошибок — заявлено явно.

## Ограничения

- Базу `cybersecurity_ontology` (старую) не изменять.
- Схему `cybersecurity_ontology_v2` в ходе прогона не менять.
- Промпт извлечения не редактировать.
- Прогон не должен блокировать API: одновременно не более 3 чанков в работе.
