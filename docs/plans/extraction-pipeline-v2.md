# Новая схема извлечения графа (v2) — по образцу щупа, параллельно существующей

Основание: замеры 11.10.2026. Щуп (`scripts/bakeoff/probe_chunks.py`) на чистом документе даёт
81 процент подтверждённых цитат, а конвейер на том же документе — 0. Разница не в модели и не в
провайдере (оба используют deepseek-v4-flash, температура 0.05, размышления отключены), а в том,
ЧТО и КАК отправляется. Новая схема переносит в продукт ровно то, что доказано щупом.

## Что делает щуп (и что переносим)

1. Системная часть — минимальная и язык-нейтральная (в щупе её нет вовсе; в продукте — одна строка).
2. В запросе ПОЛЬЗОВАТЕЛЯ лежит: список типов связей, сам фрагмент ЦЕЛИКОМ, ОБРАЗЕЦ ответа с полем
   подтверждения и правила. Образец — обязателен: доказано, что без него модель не отдаёт цитату,
   а строгая формулировка «нет цитаты — не выводить» даёт пустой ответ.
3. Правила мягкие: «выведи все связи, для каждой дай дословную цитату; не подобрать — null,
   но связь выведи». Запрет вывода парализует модель.
4. Разбор ответа терпимый: снимает markdown-обёртку, берёт от первой фигурной скобки до последней.
5. Проверка цитаты — по нормализованному тексту (только буквы и цифры), применяется и к свежему
   извлечению, и к ответу из кэша.
6. Цитата СОХРАНЯЕТСЯ на связи в графе (поле evidence) — доказательство рядом с фактом.

## Чего в конвейере НЕ делать (найденные дефекты)

- Не подставлять в запрос урезанный фрагмент: медиана фрагмента 1572 знака, максимум 1725, а в
  запрос уходили первые 1000 — модель не видела треть текста, проверка её не подтверждала.
- Не подставлять типы связей из доменной схемы документа, если она пуста: модель без списка типов
  отвечает пустым списком связей. Брать полный словарь онтологии (prompt_rules).
- Не терять поле при разборе: разбор строил связь заново из source/target/type и выбрасывал цитату.
- Не делать отпечаток кэша из частей запроса: правки шаблонов при неизменном отпечатке возвращали
  старые ответы (три прогона подряд давали одни и те же числа).

## Как встроить ПАРАЛЛЕЛЬНО (ничего не ломая)

Настройка `system/graph_quality.extraction_scheme`: `current` (как сейчас) | `v2` (новая схема).
Новая схема — отдельный модуль `src/indexing/extraction_v2.py` с одной точкой входа:
`extract_chunk_v2(chunk_text, chunk_id, cfg) -> {"entities": [...], "relations": [...]}`
(связи — с полем evidence). Выбор схемы — в одном месте, где сейчас вызывается `extract_from_chunk`.
Старая схема остаётся рабочей и переключается обратно той же настройкой.

## Порядок работы

1. Модуль v2 + переключатель; по умолчанию остаётся `current`.
2. Замер на фиксированных фрагментах ГОСТ 57580 (щуп и v2 должны совпасть по доле подтверждённых).
3. Проверка на целом ГОСТ 57580 со строгим режимом: доля подтверждённых около 80 процентов,
   цитата видна в графе.
4. Пятёрка документов — по решению владельца.
5. Переключение по умолчанию на v2 и пересборка корпуса.

## Метрики приёмки

- Доля связей с цитатой, найденной в тексте фрагмента: не ниже 75 процентов (щуп даёт 81).
- Ноль неразобранных ответов.
- У каждой записанной связи в графе есть непустое поле evidence.
- Число связей с точным типом не падает относительно текущей схемы.
