# Что взято у Palantir и как это у нас выглядит

Источник — практический чек-лист проектирования онтологий Palantir Foundry
(https://www.palantir.com/docs/foundry/ontology/ontology-best-practices) и описание их модели
(тип объекта, свойство, общее свойство, тип связи, тип действия, роли, функции, интерфейсы).

| Понятие Palantir | Что это у них | Что это у нас | Статус |
|---|---|---|---|
| Тип объекта | схема сущности/события | классы Документ, Организация, Тема, Изменение | есть (граф + таблицы) |
| Свойство | характеристика объекта | номер, год, статус, вид документа | есть |
| **Общее свойство** | описывается один раз, переиспользуется между типами | «наименование», «дата», «источник» | НЕ сделано (в плане) |
| **Тип связи между ТИПАМИ** | схема отношения + проверка | `allowed_relation_types()` + проверка на записи | СДЕЛАНО 09.10.2026 |
| **Тип действия** | схема изменения человеком («действие») | `POST /admin/models/document-classification` + журнал действий | СДЕЛАНО 09.10.2026 |
| Роли | права на ресурсы онтологии | ACL (visibility/группы/пользователи), админские пути | есть |
| Интерфейсы | форма типа → композиция вместо глубоких иерархий | фасеты (предмет защиты, этап, статус, гриф) | СДЕЛАНО (фасеты) |
| Функции | кодовая логика над объектами | сервисы (`document_service`, `kg_service`) | есть |

## Анти-паттерны Palantir — проверка нашего проекта

| Анти-паттерн (их формулировка) | Как у нас |
|---|---|
| Моделировать таблицы источника, а не реальность | частично: классификация документа опиралась на «other/standard/financial» без словаря видов → **чиним словарём v0** |
| Свойства 1:1 из колонок без отбора | у нас обратное: свойства появляются из извлечения; **отбор делаем** (проверка типов связей, отказ от `RELATED_TO`-шума) |
| Имена из систем источника, а не языка предметной области | **было**: типы связей `RELATED_TO`, `ASSIGNED_TO`, русские обороты модели → **почищено 09.10.2026**, теперь закрытый словарь |
| Модель построена по данным, а не по пониманию домена | **было** (словарь никто не задавал, промпт типы не перечислял) → **исправляем**: словарь v0 + разметка |
| Одна строка источника = один тип объекта | нет |
| Смешение разных осей в одной иерархии | **было** (домен/вид документа/издатель в одном дереве) → разделено на три оси + фасеты |

Вывод: три наших главных анти-паттерна (имена из системы, модель по данным, смешение осей) уже
исправлены или исправляются словарём; на очереди общие свойства и словарь видов документа.
