# Дорожная карта семантики и конвейера KAG (рабочий список задач)

Начата 09.10.2026 по итогам диалога с владельцем (разбор и источники — `docs/research/semantics-and-relations.md`).
Владелец: «работай, проектируй, тестируй, выполняй, иногда останавливайся доложить».
Приоритеты, названные владельцем: **правильная архитектура, эффективность ресурсов, скорость, точность, масштабирование**.

Главный принцип (согласован): **текущую базу не латаем** — собираем новую правильно. Текущий корпус —
полигон: он дешёв в пересборке (~8,5 ч на 279 документах) и нужен как материал для тренировки конвейера.
Хранить обязательно **сырьё** (файлы, разобранный текст и таблицы, хеши, метки времени); граф и векторы —
производные.

Цель по объёму: **10 000 документов**. 50 000 — второй этап, отдельный проект.

## A. Семантика: словарь и модель

- [ ] **A1. Словарь видов документов (черновик v0)** — по образцу ФЗ-162 (национальные стандарты,
      классификаторы, стандарты организаций включая ТУ, своды правил) плюс бытовые виды из корпуса
      (письмо, приказ, указание, доклад, договор, счёт, акт, накладная, доверенность, бланк-форма).
      Приёмка: каждый вид с определением и примером; не более 25 видов.
- [ ] **A2. Словарь связей (черновик v0)** — по образцу DataCite + Winston (виды «части»): часть_целого,
      новая_редакция, ссылается_на, изменяет, отменяет, основан_на, принадлежит_к, упоминается.
      Один смысл = один тип; синонимы только в подписи.
      Приёмка: у каждого типа направление (кто→кого), какие классы соединяет, 2-3 примера из корпуса,
      «не путать с».
- [ ] **A3. Фасеты** — закрытые перечни: предмет защиты (данные/сети/люди/серверы/сервисы), этап
      (проектирование/эксплуатация/вывод), статус, нормативная сила, гриф. Процессы не моделируем.
      Приёмка: значение фасета можно проставить несколькими (многозначность) и не проставлять вовсе.
- [ ] **A4. Тема (рубрика)** — дерево домен→аспект, МНОГОЗНАЧНОЕ и мягкое: по умолчанию не ограничивает
      поиск. Явная пометка в коде и тест, запрещающий жёсткий фильтр по теме по умолчанию.
- [ ] **A5. Тип связи объявляется между ТИПАМИ и проверяется на записи** (урок Palantir). Незнакомый тип
      не пишется, а попадает в журнал отказов.
- [ ] **A6. Юридическая ось** — отложено владельцем; вернуться только если понадобится механизм
      «обязательство → доказательство».

## B. Архитектура новой базы

- [ ] **B1. Происхождение каждого факта** — документ, страница, фрагмент, версия извлекателя и промпта.
      Приёмка: у любой связи/сущности можно спросить «откуда» и получить страницу и фрагмент.
- [ ] **B2. Версия схемы и конвейера у каждого факта.** Приёмка: при смене словаря старые факты отличимы,
      переобработка всего корпуса не требуется.
- [ ] **B3. Хеш файла и метка времени при загрузке** — один раз, в неизменяемом журнале.
- [ ] **B4. Вид, тема, фасеты, издатель — как поля данных**, а не вывод модели на лету.
- [ ] **B5. Связь редакций** — «тот же документ в новой редакции» (механизм `SUPERSEDED_BY` уже есть).
- [ ] **B6. Сырьевой слой как отдельный артефакт** — разобранный текст/таблицы/страницы хранится и
      переиспользуется: пересборка графа и векторов не запускает OCR заново.
      **Проверено 09.10.2026:** 14 из 14 текстовых фрагментов Qdrant находятся в Neo4j ПО ТОМУ ЖЕ
      идентификатору (`<document_id>_chunk_NNNNN`) — распознанный слой уже переиспользуем, повторное
      распознавание не требуется. Служебные фрагменты карточек (`card`) узлов `Chunk` не имеют — это
      норма, в счёт не идут. Прибор: `scripts/bakeoff/check_chunk_ids.py`.
- [ ] **B7. Хранилище графа** — модель описываем независимо от движка; решение о смене (Kuzu, Postgres+AGE)
      только по замеру обходов и памяти; лицензии (GPLv3 Community / DozerDB) — пункт поставки.
- [ ] **B8. Пересборка фоном** — blue-green через алиасы Qdrant + идемпотентные id точек + журнал
      «что переработано»; граф — новая база рядом со старой, затем переключение.
      Остаток к унификации: в Qdrant `point_id` — производный `uuid5(doc_id-i)`, а идентификатор
      фрагмента лежит в payload (`chunk_id`). Сделать `point_id = uuid5(chunk_id)` (пункт плана
      12.09.2026) — тогда ключ один и пересборка не зависит от payload.

## C. Конвейер: скорость и точность

- [ ] **C1. Убрать квадратичный шум `RELATED_TO`** (полный граф пар сущностей документа): либо убрать,
      либо сущность→документ (линейно), либо только пары внутри фрагмента. Замер до/после: число связей,
      размер графа, время обработки документа.
- [ ] **C2. Приём JEV** — закрытые вопросы с вероятностями для: типа связи, вида документа, рубрики,
      фасетов, анализа вопроса чата, оценки релевантности. Пороги: >0,9 применить, 0,6–0,9 на проверку,
      <0,6 не применять. Пороги калибровать замером.
- [ ] **C3. Локальный «ученик»** — JEV как учитель: разметить выборку, обучить/проверить локальный
      классификатор, работающий в закрытом контуре. JEV в рантайме продукта НЕ используется (облако).
- [ ] **C4. Модель-каскад** — мелкая модель на маршрутизацию/классификацию, крупная только на финальный
      ответ; батчинг и кэш по хешу текста.
- [ ] **C5. GPU-путь как основная конфигурация** (vLLM/локальная модель с батчами), CPU — режим отладки.
- [ ] **C6. Проверка кодировки при разборе** — битый текст не должен попадать в извлечение.
- [ ] **C7. Нормализация типа файла** — один формат вместо 11 вариантов.
