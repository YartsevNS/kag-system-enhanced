# Словарь семантики v0 (УТВЕРЖДЁН 10.10.2026)

Словарь к дорожной карте `docs/plans/semantics-and-pipeline-roadmap.md` (пункты A1–A3).
Статус: **утверждён владельцем 10.10.2026 как основной.** Код словаря живёт в
`src/indexing/document_kinds.py` — это ЕДИНСТВЕННЫЙ источник (перечисление анализатора, фильтры и
подписи страниц, список типов в админке, правила авто-разметки берут значения оттуда).
Старый набор значений в базе переводится в него прибором `scripts/bakeoff/migrate_document_types.py`
(сухой прогон по умолчанию, запись — через админский эндпоинт правки разметки, то есть с журналом).

Отличия утверждённой версии от черновика:

* добавлен `preliminary_standard` (ПНСТ) — ровно **25 видов**, как в пороге приёмки «не более 25»;
* `classifier` (общероссийский классификатор) в словарь НЕ взят: в корпусе таких документов нет
  (кандидат в техдолг — вернуться, когда появится спрос);
* вида `news` в словаре НЕТ намеренно: «новость» — признак ИСТОЧНИКА, а не вид документа.
  Маршрут коллекции (`kag_documents` / `kag_news`) задаётся полем `documents.collection`,
  его ставит загрузка по метаданным источника; разметка на маршрут не влияет.

Правило: код типа — латиницей (стабильный, безопасный для движка), русское название — только для показа.

## 1. Три оси + фасеты (напоминание модели)

- **Тема (рубрика)** — дерево «домен → аспект», МНОГОЗНАЧНОЕ, по умолчанию не ограничивает поиск.
- **Вид документа** — один на документ, из словаря ниже.
- **Издатель** — ссылка на класс «Организация».
- **Фасеты** — независимые перечни, могут быть пустыми и многозначными.

## 3. Типы связей (ядро v0)

Код латиницей; поля обязательны ко всем: определение, направление, классы, пример, «не путать с».

### 3.1. Документ → Документ (основание: словарь DataCite, `relatedIdentifier`)

| Код | Название | Определение | Не путать с |
|---|---|---|---|
| `part_of` | часть целого | документ входит в состав другого (приложение, изменение, раздел, часть) | `belongs_to` (членство в серии), `new_edition_of` |
| `new_edition_of` | новая редакция | заменяет другой как более новая редакция ТОГО ЖЕ документа | `amends` (изменение не заменяет документ), `part_of` |
| `references` | ссылается на | в тексте есть прямая ссылка на другой документ | `based_on` (разработан на основе, а не сослался) |
| `amends` | изменяет | документ изменения вносит правку в другой документ | `new_edition_of` (изменение не новая редакция), `part_of` |
| `repeals` | отменяет | признаёт другой документ утратившим силу | `new_edition_of` (замена ≠ отмена) |
| `based_on` | основан на | разработан на основе другого документа | `references` |
| `belongs_to` | принадлежит к | членство: стандарт принадлежит серии, организация — группе | `part_of` (вложенность) |

### 3.2. Документ → Организация / лицо / значение

| Код | Название | Направление | Пример |
|---|---|---|---|
| `issued_by` | издан организацией | Документ → Организация | Приказ издан Банком России |
| `adopted_by` | принят организацией | Документ → Организация | стандарт принят организацией |
| `addressed_to` | адресован | Документ → Организация/Лицо | информационное письмо адресовано подразделениям |
| `dated` | датирован | Документ → Дата | договор от 09.11.2020 |
| `for_amount` | на сумму | Документ/Обязательство → Сумма | договор на 3,5 млн руб |
| `signed_by` | подписан | Документ → Лицо | акт подписан директором |
| `located_at` | расположен | Организация/Объект → Место | организация по адресу |

### 3.3. Системные (нужны конвейеру, не для человека)

| Код | Назначение |
|---|---|
| `mentions` | фрагмент упоминает сущность (существующая `MENTIONS`) |
| `has_chunk` | документ содержит фрагмент (существующая `HAS_CHUNK`) |
| `related_to` | **временная** общая связь: связи строятся только ВНУТРИ фрагмента (правка 10.10.2026).
   Глобальная доля `RELATED_TO` в графе — 0,35% (471 из 134 994): прежняя цифра «74%» была снята
   по ОДНОЙ сущности и на весь граф не распространяется. Основной объём — структурные связи
   «фрагмент упоминает сущность». См. C1 дорожной карты |

## 4. Фасеты (закрытые перечни)

Единый источник — `src/indexing/document_facets.py` (код живёт там). Фасетов у документа может не
быть вовсе; у одного фасета значений может быть несколько (многозначность).

| Фасет (код) | Название | Значения (код — что значит) |
|---|---|---|
| `protection_subject` | Предмет защиты | `data` данные и ПДн · `networks` сети и связь · `people` люди · `servers` серверы и оборудование · `services` процессы и ИС · `not_applicable` документ не про защиту |
| `normative_force` | Нормативная сила | `mandatory` обязательные требования · `recommended` рекомендации · `informational` справочная информация |

В реестр входят ТОЛЬКО эти два фасета: они размечены в пилоте JEV с уверенностью 0,83, то есть под
них есть материал. Черновые `stage` (этап), `status` и `classification_mark` (гриф) в реестр НЕ
добавлены — разметкой они не проверялись, а «настройка, за которой нет кода» — дефект (стража —
`tests/test_document_facets.py`).

## 5. Тема (рубрика): первый уровень

Единый источник — `src/indexing/document_topics.py` (код живёт там, здесь — только описание).
Код латиницей, подпись по-русски; тема МНОГОЗНАЧНА и МЯГКА (не ограничивает поиск; страж —
`tests/test_document_topics.py`).

| Код | Название | Что внутри |
|---|---|---|
| `infosec` | Информационная безопасность | защита информации, криптография, СЗИ, электронная подпись, аудит ИБ |
| `law` | Юриспруденция | право, нормативные акты, судебная практика (сквозная тема) |
| `banking` | Банковское регулирование | Банк России, надзор, поднадзорные организации |
| `economics` | Экономика и финансы | экономика, финансы, статистика, рынки, бухгалтерский учёт |
| `it` | Информационные технологии | ИТ, вычислительная техника, связь |
| `ai` | Искусственный интеллект | машинное обучение, нейросети, ИИ |
| `medicine` | Медицина | медицина, здравоохранение, препараты и изделия |
| `fire_safety` | Пожарная безопасность и охрана труда | пожарные требования, охрана труда |
| `hr` | Управление персоналом | кадры, трудовые отношения, обучение |
| `other` | Иное | тема не определена либо словарь не покрыл случай |

Аспекты (второй уровень) наполняются внутри домена по мере разметки, а не выдумываются заранее.
Легаси-домены прежней схемы переносятся в темы прибором `scripts/bakeoff/migrate_domain_to_rubrics.py`
(`infosec`→`infosec`, `legal`→`law`, `accounting`→`economics`, `universal` — это НЕ тема).

## 6. Как проверяем (что должно случиться дальше)

1. Разметка 500 фрагментов через JEV по этому словарю: вид документа, рубрика, фасеты, тип связи между
   парами сущностей. Смотрим: долю уверенных ответов (>0,9), долю «other», какие варианты модель
   путает (`part_of` vs `belongs_to` — главный риск).
2. Правки словаря по фактам разметки (не по воображению).
3. Только после этого — перенос словаря в код: проверка типов на записи, поля в данных, локальный
   «ученик» вместо облачной модели.
