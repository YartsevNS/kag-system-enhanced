# Задание модели на извлечение связей (текущая версия, 11.10.2026)

Готовый текст задания, которое модель читает перед разбором каждого фрагмента. Оно управляет тем, какие
связи попадут в граф.

Собрано из трёх источников: (1) наши замеры отказов словаря на реальном корпусе, (2) литература по
части-целому (Winston 1987; Keet; Wikidata P749), (3) ответ внешней модели на наш вопрос
(`docs/research/вопрос-внешней-модели-принадлежит.md`).

Что взято у внешней модели: жёсткий разбор слова «принадлежит» (оно запрещено как готовый тип — надо
выбирать точный), обязательное поле `evidence` (цитата из текста, на которой основана связь),
отдельный тип `effective-from` (дата вступления в силу, не путать с датой подписания).

Что осталось нашим и не взято у неё: `located-at` (адрес — обязателен в нашем домене) и связи STIX для
безопасности (`targets`, `indicates`, `mitigates`) — у нас первый домен информационная безопасность.
Обратные связи (`has-component`, `has-member`) отдельными типами не заводим: обратное получается
обходом графа, а держать оба направления — удваивать число связей и мест для ошибки.

Задание формируется кодом: `src/indexing/graph_ontology.py`, функция `prompt_rules()`. Страница в
админке: **/graph-prompt** («Связи графа»). Здесь — его текст, чтобы читать и обсуждать не заходя в код.

Цена: около 10 тысяч знаков, уходит в каждый вызов извлечения. Это прямая плата за точность; сокращать
надо в первую очередь примеры у типов, которые модель и так выбирает правильно.

---

```text
ЗАДАЧА: для каждого фрагмента текста извлечь сущности и связи МЕЖДУ НИМИ.
Связь описывается только типом из списка ниже. Код пиши латиницей ровно как указано.

ГЛАВНОЕ ПРАВИЛО ПРОВЕРКИ (нарушение = связь не попадёт в граф):
1. Тип связи — только из списка.
2. Пара «тип источника → тип цели» должна быть среди разрешённых для этого типа.
3. Если подходящего типа нет — оставь related-to. Изобретать типы запрещено.

component-of («структурная часть») — СТРУКТУРНАЯ часть документа: пункт в документе, раздел в разделе, редакция в деле. Не про организации и не про термины — для них member-of, subordinate-to, broader-term
   допустимо: clause → standard; clause → document_ref; clause → clause; document_ref → document_ref; standard → standard; document_ref → standard; standard → document_ref; standard → clause
   верно: пункт 5.2 component-of ГОСТ Р 57580.1
   верно: раздел 2 component-of стандарт
   НЕВЕРНО: ГОСТ component-of Росстандарт — это издатель (issued-by)
   НЕВЕРНО: подразделение component-of организация — это member-of

member-of («состоит в») — лицо или организация входит в объединение или подчинена другой организации
   допустимо: person → organization; organization → organization

attributed-to («отнесено к») — документ или событие отнесено к организации (кто отвечает, чьё это)
   допустимо: document_ref → organization; event → organization; standard → organization

authored-by («подготовлено») — документ подготовлен организацией или лицом
   допустимо: document_ref → organization; document_ref → person; standard → organization

derived-from («основано на») — документ создан на основе другого документа или стандарта
   допустимо: document_ref → document_ref; standard → standard; standard → document_ref; document_ref → standard

targets («воздействует на») — угроза, инцидент или требование направлены на объект
   допустимо: event → organization; event → document_ref; document_ref → document_ref; legal_term → organization

indicates («указывает на») — признак или показатель указывает на событие, угрозу либо нарушение
   допустимо: legal_term → event; event → event; document_ref → event

mitigates («снижает») — мера, средство или требование снижает риск или угрозу
   допустимо: document_ref → event; legal_term → event; standard → event

amends («изменяет») — документ вносит изменения в другой документ
   допустимо: document_ref → document_ref; standard → standard

repeals («отменяет») — документ отменяет или прекращает действие другого документа
   допустимо: document_ref → document_ref; standard → standard

corrects («исправляет») — документ исправляет ошибки другого документа
   допустимо: document_ref → document_ref

consolidates («объединяет») — документ объединяет положения нескольких документов
   допустимо: document_ref → document_ref

references («ссылается на») — документ ссылается на другой документ, стандарт или пункт
   допустимо: document_ref → document_ref; document_ref → standard; standard → standard; standard → document_ref; document_ref → clause; standard → clause

subordinate-to («подчинено») — организация административно подчинена другой (министерство → агентство → подведомственная организация). Частично транзитивна
   допустимо: organization → organization
   верно: ФГУП «Стандартинформ» subordinate-to Росстандарт
   верно: территориальное управление subordinate-to министерство
   НЕВЕРНО: Минтранс subordinate-to Правительство РФ — это часть или членство, не подчинённость
   НЕВЕРНО: ГОСТ subordinate-to Росстандарт — у документа не бывает подчинённости, это издатель

broader-term («шире по смыслу») — термин шире или уже другого термина (иерархия классификаторов и предметных областей; стандарт SKOS: broader/narrower). Заменяет ложное «входит в состав» вида «стандарт → область знаний»
   допустимо: legal_term → legal_term
   верно: криптографическая защита информации broader-term информационная безопасность
   НЕВЕРНО: ГОСТ Р 34.14 broader-term Информационная технология — документ не термин; тема документа это рубрика, а не связь терминов

classified-as («отнесено к рубрике») — документ отнесён к рубрике, области или классу. Это КЛАССИФИКАЦИЯ, а не смысловая связь: нужна для поиска по рубрикам, по цепочкам не ходит
   допустимо: document_ref → legal_term; standard → legal_term
   верно: ГОСТ Р 34.14 classified-as криптографическая защита информации
   НЕВЕРНО: ГОСТ Р 34.14 classified-as Росстандарт — организация это издатель (issued-by), а не рубрика

adopted-by («принято») — документ принят или утверждён решением органа (голосование, утверждение)
   допустимо: document_ref → organization; standard → organization
   верно: ГОСТ Р 34.14 adopted-by Росстандарт
   верно: устав adopted-by совет директоров
   НЕВЕРНО: статья adopted-by автор — статья не принимается органом

in-collection («входит в сборник») — документ входит в комплект, сборник или пакет документов (приложение, дополнение, свод)
   допустимо: document_ref → document_ref
   верно: приложение № 1 in-collection приказ № 5
   НЕВЕРНО: ГОСТ in-collection Росстандарт — это издатель, а не сборник

has-part («содержит») — документ содержит пункт, раздел, таблицу или приложение
   допустимо: document_ref → clause; standard → clause; document_ref → document_ref; clause → clause

is-version-of («является редакцией») — документ является новой редакцией, версией или переводом другого
   допустимо: document_ref → document_ref; standard → standard

replaces («заменяет») — документ заменяет другой (взамен ранее выпущенного)
   допустимо: document_ref → document_ref; standard → standard

requires («требует») — документ требует наличия другого документа или условия
   допустимо: document_ref → document_ref; standard → standard; document_ref → legal_term

signed-by («подписано») — документ подписан лицом или организацией
   допустимо: document_ref → person; document_ref → organization

issued-by («издано») — документ издан или утверждён органом
   допустимо: document_ref → organization; standard → organization

effective-from («действует с») — дата вступления документа в силу. Отдельно от dated: дата подписания и дата вступления в силу у нормативных документов различаются
   допустимо: document_ref → date; standard → date
   верно: приказ effective-from 1 марта 2026 г.
   НЕВЕРНО: приказ effective-from дата подписания — это dated

dated («датировано») — документ или событие имеет дату
   допустимо: document_ref → date; organization → date; person → date; standard → date; event → date

has-amount («на сумму») — документ или организация связаны с суммой
   допустимо: document_ref → money; organization → money; money → money

defines («определяет») — документ или стандарт определяет термин
   допустимо: document_ref → legal_term; standard → legal_term

applies-to («распространяется на») — документ распространяется на кого или что-либо
   допустимо: document_ref → organization; document_ref → legal_term; document_ref → person; standard → organization

establishes-requirement («устанавливает требование») — документ, стандарт или пункт устанавливает требование к чему-либо
   допустимо: document_ref → legal_term; standard → legal_term; clause → legal_term

related-to («связано с») — связь есть, но её тип определить не удалось
   допустимо: пары не проверяются

РАЗБОР ПУТАНИЦЫ «кто причастен к документу» — отвечай на вопрос по очереди:
   кто дал документу юридическую силу (официально выпустил, издал)? → issued-by
   кто утвердил или принял решением (голосование, постановление)? → adopted-by
   кто подписал (должностное лицо, подпись)? → signed-by
   кто написал или разработал текст (автор, рабочая группа, институт)? → authored-by
   чьё мнение или чья работа упомянута в тексте? → attributed-to
   организация подчинена другой? → subordinate-to. Лицо или организация ВХОДИТ в объединение? → member-of
ВНИМАНИЕ: издатель, автор, подписант и принявший орган — это РАЗНЫЕ связи, не одна.

СЛОВО «ПРИНАДЛЕЖИТ» — ПОД ЗАПРЕТОМ. Если в тексте написано «принадлежит», «относится»,
«входит в» — это НЕ готовый тип связи, а приглашение подумать. Выбери по смыслу:
   структурная часть текста → component-of;   членство в коллективе → member-of;
   подчинённость организации → subordinate-to;   входит в сборник → in-collection;
   организация выпустила документ → issued-by;   тематика/рубрика → classified-as.

ЧЕГО НЕ ДЕЛАТЬ (частые ошибки на нашем корпусе):
   не связывай документ с организацией как с частью целого: частью документа организация не бывает;
   не связывай документ с предметной областью («Информационная технология», «Криптографическая
   защита информации») — для этого есть classified-as, и это рубрика, а не смысловое отношение;
   не обозначай часть-целое словом «принадлежит» — выбери component-of, member-of,
   subordinate-to или in-collection по смыслу;
   не ставь has-amount для номера документа (№ 1070-ст) — это номер, а не сумма;
   не ставь dated термину или понятию — датируют документ или событие.

ТИПЫ СУЩНОСТЕЙ: document_ref (документ или его номер), legal_term (термин, понятие, требование), organization (организация, орган власти), person (человек (подписант, должностное лицо)), date (дата), money (сумма, стоимость), location (место, адрес), standard (стандарт, свод правил (ГОСТ, СП, СНиП)), clause (пункт, раздел, таблица, приложение), event (событие)

ПОРЯДОК РАБОТЫ (сначала решай, потом отвечай):
   шаг 1 — найди сущности и определи их типы;
   шаг 2 — для каждой возможной пары сначала назови вопрос из разбора выше и реши его;
   шаг 3 — выбери код из списка и проверь пару по разрешённым;
   шаг 4 — выдай JSON.

ОБЯЗАТЕЛЬНОЕ ПОЛЕ evidence: для каждой связи приведи КОРОТКУЮ ЦИТАТУ из текста, на которой она
основана (до 12 слов). Связь без цитаты считается выдуманной и будет отброшена. Это правило
существует потому, что каждая связь в графе должна быть проверяема по источнику.
В поле relation_reasoning — одна короткая фраза, почему выбран тип (для разбора, в ответы
пользователю не попадает).
```
