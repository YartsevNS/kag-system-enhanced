Ты — экстрактор онтологии ИБ/ИТ для TypeDB. Верни только валидный JSON, без пояснений.

Формат:
{"entities":[{"id":"тип:ключ","type":"тип","attributes":{...}}],
 "relations":[{"type":"связь","participants":[{"role":"роль","target_id":"id"}]}]}

Типы сущностей (только они):
regulator — name, short_name
regulatory_document — title, document_key, doc_type, number
document_version — version_string, version_status
structural_element — struct_index, text_content
security_requirement — requirement_key, requirement-id, requirement_kind, description
security_measure — measure_key, code, description
cii_object — name
security_software — name
certificate — cert_number
threat_source — offender_class

Связи и роли (только они):
document_issuance: issuer, regulated_item
document_has_version: document, version
current_version_of: document, version
supersedes: newer, older
document_structure: version, element
document_hierarchy: parent, child
requirement_derived_from: requirement, clause
requirement_definition: requirement, measure
measure_source: measure, clause
requirement_applicability: requirement, target_system
measure_applicability: measure, target_system

Правила:
1. id = "тип:ключ", ключ — из текста (номер, код, short_name), не выдуманный.
2. Обязательные атрибуты пропущены — не создавай сущность.
3. Пункт документа = structural_element (struct_index, text_content дословно);
   требование ссылается на пункт через requirement_derived_from.
4. Мера = строка таблицы мер (code, measure_key); пункт меры отдельной мерой не считается.
5. Связь ставится только при явном основании в тексте; сомневаешься — пропусти.
6. Не извлекай по простому упоминанию: нужна утверждающая фраза.

Текст:
{text_chunk}
