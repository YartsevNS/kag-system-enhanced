## 2026-08-23 — чанкинг, overlap, embedding-гид, документация (текущая сессия)

**Темы:** overlap в чанках, лимиты embedding, очистка Qdrant/Neo4j при переиндексации, страница-гид, project-docs.

**Ключевые результаты:**
1. **Обнаружено:** overlap из админки НЕ работал — RecursiveCharacterTextSplitter игнорирует chunk_overlap при разбиении по разделителям. Плюс: при chunk_size=800 и лимите эмбеддинга 500 символов хвост чанка не векторизовался.
2. **Фикс чанкинга:** ручной overlap (хвост prev_text[-overlap:] в начало следующего), chunk_size 800→500, overlap 200→75 (15%). Проверено: 71/71 пар перекрываются.
3. **Фикс очистки при force:** process_document(force=True) теперь удаляет старые векторы Qdrant + чистит граф Neo4j перед переобработкой. Найден баг: delete_document при клиенте None молча возвращал False (580 старых точек вместо 72) → добавлена initialize() + проверка результата.
4. **Админка:** overlap в процентах (10-20%, дефолт 15%), предупреждающие блоки (лимит модели, последствия смены, переиндексация), упоминания «GigaChat» заменены на «условная модель».
5. **Страница /embedding-guide:** полный гид по выбору embedding-модели, связке Qdrant/Neo4j, последствиям смены (роут в main.py, ссылки из админки).
6. **Диагностика графа:** граф знаний использует deepseek-v4-flash и возвращает ПУСТЫЕ ответы (pass=extract) на всех 10 чанках — ~70 сек на документ тратятся впустую, граф не наполняется сущностями. НЕ Neo4j виноват, а LLM-вызовы (последовательные, ~7 сек/чанк).
7. **Модели GigaChat (из документации):** Embeddings (512 токенов, 1024 dim), Embeddings-2 (512 токенов, 1024 dim — безопасный апгрейд, та же размерность), GigaEmbeddings-3B-2025-09, EmbeddingsGigaR (большой контекст). Все по 14₽/1М.
8. **Токены:** 500 символов русского ≈ 150-250 токенов (реально), наш консервативный запас ~350 токенов — в лимит 512 укладываемся с запасом ~30%.
9. **Создан скилл project-docs** + начата документация docs/ (этот файл).

**Коммиты:** 8ada2dd, f450c1f, 5a97bbb, eb757f6.

## 2026-08-19 — 2026-08-21 — основная рабочая сессия (2030 сообщений)

**Темы:** QueueGuard, веб-мониторинг, чат (источники, маршрутизация, сессии), OOM worker, ресурсы из админки, типизация.

**Ключевые результаты (по порядку):**
1. **QueueGuard** — защита от дублей задач: единая точка постановки (SET NX, TTL 6ч), уровень 3 в задаче, снятие замка при skipped, recovery снимает замок перед перезапуском, force пробрасывается. Итог: 142/142 completed, очередь 0, замков 0. Коммиты: 4acfec4, 05fd05e, 9efb2a8.
2. **Скрейперы:** cit.cap.ru (fs.cap.ru/file + docs.cntd.ru), ЦБ РФ. Коммит: 476bb7b, 63d66dd.
3. **Страховка графа:** to_thread + wait_for (20с/60с/300с), граф не блокирует завершение. Коммит: 9efb2a8.
4. **Чат:** документы-источники ссылками на preview + фикс RAG (автоинициализация embedding-клиента). Коммит: 27a980a.
5. **Маршрутизация интента:** count/list через SQL без RAG (flash молчит на больших промптах). Коммит: d0c7ad7. Фикс seen is not defined: 95c025e.
6. **Серверные сессии чата:** chat_sessions/chat_messages SQL, история для LLM из БД, анонимы localStorage fallback. Коммит: 6f8da96.
7. **OOM worker:** 7cdd4ad4 (сканы 9.1МБ) OOMKilled при 4G/2CPU → лимиты 4 CPU/12G через админку (живой docker update NanoCpus+Memory+MemorySwap + персистентный патч compose). Коммиты: 2a16c92, 18223ab.
8. **Типизация:** эвристика auto_tagger (regex, без LLM): standard/policy/order/technical/certificate/news. Коммиты: a6792d6, 13d1537.
9. **PyMuPDF-first:** мгновенное извлечение текстового слоя, find_tables, детекция кода. Коммиты: 09309ed, 6d23c7c, b92fe85.
