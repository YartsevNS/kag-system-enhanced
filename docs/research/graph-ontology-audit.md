# Аудит онтологии графа: качество связей, за которые уже заплачено (10.10.2026)

Задача: прежде чем что-либо перестраивать, измерить качество существующего графа. Токены на него уже
потрачены, а качество не измерялось ни разу. Прибор `scripts/bakeoff/graph_ontology_audit.py` проверяет
связи по схеме «тип сущности — связь — тип сущности». Он ничего не меняет — только считает.

## 1. Числа

Всего связей **135 468**: системных (их пишет код, а не модель) 87 235, смысловых (от модели) **48 233**.

| Категория смысловых связей | Сколько | Доля |
|---|---|---|
| Проходят проверку по схеме | 13 114 | **27,2%** |
| Нарушают схему (пара типов недопустима) | 8 019 | **16,6%** |
| Не проверялись — у типа связи нет заданной семантики | 27 100 | **56,2%** |

Дублирующихся связей нет — это хорошая новость: код дедупликацию держит.

По типам связей:

| Тип | Всего | Проходит | Нарушает | Доля брака |
|---|---|---|---|---|
| `BELONGS_TO` | 26 845 | — | — | семантика не определена (56% всех смысловых связей!) |
| `DATED` | 9 528 | 8 104 | 1 424 | 15% |
| `LOCATED_AT` | 6 860 | 3 357 | 3 503 | **51%** |
| `SIGNED_BY` | 2 375 | 1 087 | 1 288 | **54%** |
| `AMOUNT` | 2 343 | 539 | 1 804 | **77%** |
| `RELATED_TO` | 255 | — | — | запасной тип, пар не проверяем |
| `SUPERSEDED_BY` | 27 | 27 | 0 | чисто (но всего 27 связей — это самые важные «кто кого отменяет») |

Крупнейшие нарушения (смысл очевиден без пояснений):

* `LOCATED_AT`: **место → место** (1409), юр. термин → место (370), организация → организация (294) —
  модель использует «находится» как общую ассоциацию, а не как «расположение объекта в месте»;
* `AMOUNT`: юр. термин → сумма (353), юр. термин → юр. термин (305);
* `SIGNED_BY`: **человек → человек** (306), организация → человек (168);
* `DATED`: сумма → дата (264), **дата → организация** (212), дата → дата (193).

## 2. Корневая причина — найдена и она в промпте

Промпт извлечения (`function_map.graph.system_prompt`, взят с рабочего стенда) ограничивает ТИПЫ
СУЩНОСТЕЙ («type — только из переданного списка типов сущностей»), а про связи говорит лишь
«source и target связи — только из найденных сущностей». **Типы связей модель не ограничены вообще.**

Отсюда два следствия:

1. `BELONGS_TO` стал мусоркой: в него свалено 26 845 связей (56% смыслового графа) с парами вида
   «юр. термин → юр. термин», «документ → документ», «человек → организация». Это не «принадлежит» —
   это «что-то как-то связано», то есть по такому ребру нельзя ни искать, ни доказывать.
2. Проверка, которая у нас есть (`allowed_relation_types()`), фильтрует только ИМЯ типа связи. Пару
   «тип — связь — тип» не проверяет никто, поэтому `SIGNED_BY` может идти от человека к человеку.

Отдельно: 47 940 из 48 233 смысловых связей помечены версией `legacy`, то есть построены до того, как мы
ввели версионирование извлечения. Разложить брак по версиям промпта на этом графе нельзя — это цена
того, что версия схемы появилась позже. Впредь это не повторится.

## 3. Что из этого следует (выводы)

1. **Смысловой граф сейчас доверия не заслуживает**: по схеме проходит 27% смысловых связей, ещё 56%
   вообще без семантики. Опираться на эти рёбра в ответах — риск, а не опора.
2. **Перестраивать вслепую нельзя.** Если запустить переобработку с текущим промптом, получится тот же
   результат: сначала должна быть ОПРЕДЕЛЕНА онтология связей (закрытый список с осмысленными именами и
   допустимыми парами), и только потом перестройка имеет смысл.
3. **Материал для перестройки дешевле, чем кажется.** Сущности и структура (документ → раздел → фрагмент)
   в порядке: 37 189 сущностей с типами, дублей связей нет. Плох только смысловой слой — а он
   перестраивается инкрементально, а не «всё заново».
4. **Появился бесплатный источник точных связей.** Ссылки на ГОСТ, пункты и даты извлекаются правилами
   без модели и без единого токена — это ровно тот класс связей, которого в графе сейчас нет, а нужен он
   чаще всего («какие документы ссылаются на ГОСТ X», «что сказано в п. 5.2.1»).
5. **Цифра для приёмки.** После работ повторный прогон этого же прибора должен дать: доля «не проверялись»
   → близко к нулю (у каждого типа есть семантика), доля нарушений → около нуля, доля проходящих → 90%+.
   Сейчас: 27% / 17% / 56%.

## 4. План по графу (уточнён после замера)

1. **Определить онтологию связей** — закрытый список осмысленных типов с парами. Взять из предметной
   области, а не из головы модели: `SIGNED_BY` (документ → лицо/организация), `DATED`, `AMOUNT`,
   `LOCATED_AT`, `SUPERSEDED_BY` (документ → документ), `REFERENCES` (документ → документ/ГОСТ),
   `HAS_CLAUSE` (документ → пункт), `PART_OF`/`INCLUDES`, `APPLIES_TO`, `REQUIRES`. Мусорку `BELONGS_TO`
   разобрать по смыслу на эти типы.
2. **Слой правил без модели** (ссылки на ГОСТ/пункты/даты/номера) — заполняет самый нужный класс связей
   бесплатно и даёт эталон для проверки модели.
3. **Ужесточить извлечение**: ограничения пар в промпте + JSON-схема + проверка троек перед записью
   (сейчас проверяется только имя типа) + канонизация сущностей по нашему словарю алиасов при извлечении.
4. **Правки поведения при сбое** (таймаут 10–20 с вместо 180, параллельность на процесс, а не на
   документ) — они и делают дальнейшие замеры осмысленными.
5. **Локальная модель — позже**, когда появится железо: узкая задача «назначить тип связи между уже
   найденными сущностями из закрытого списка» резко снижает требования к модели, поэтому на CPU реальна
   не открытая разметка, а именно этот шаг.
