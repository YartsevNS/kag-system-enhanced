# Протокол приёмки движка таблиц (внешний код против нашего пути)

Назначение: сравнивать ЛЮБОЙ сторонний модуль разбора таблиц с нашим на одних и тех же
документах, одинаковыми метриками и без переделок на нашей стороне. Введён 04.10.2026.

## 1. Набор документов (фиксированный)

Сканы (нет текстового слоя) — главный случай, ради которого всё делается:

| `Квитанции-2.pdf` | квитанции, 2 таблицы на странице |

| Файл | Что внутри |

## 2. Контракт раннера (что должен уметь присланный код)

Модуль — одна функция, без побочных эффектов и без сети:

```python
def extract_tables(image_png: bytes, *, page: int = 1) -> list[dict]:
    """
    image_png — PNG-байты ОДНОЙ страницы, 200 dpi, RGB (рендер исходника мы делаем сами).
    Возврат — список таблиц, каждая:
      {
        "bbox": [x0, y0, x1, y1],        # пиксели входного изображения, обязателен
        "rows": [[str, ...], ...],        # ячейки построчно, ПЕРВАЯ строка — шапка
        "headers": [str, ...],            # = rows[0]
        "html": str,                      # необязательно, но приветствуется
        "source": "имя_модуля/модели",    # провенанс
        "seconds": float,                 # время на этой странице
      }
    """
```

Требования: только `onnxruntime` + `numpy` + `opencv-python-headless` + `Pillow` в рантайме
(никакого PaddlePaddle, torch, TensorFlow); веса внутри поставки; детерминированность (без
случайности и без прогрева из сети).

## 3. Метрики (считаются нашим кодом одинаково для всех)

1. **Числа.** Нормализация: пробелы-разделители убираются, `,` → `.`, неразрывные пробелы и
   знак валюты отбрасываются, ведущие нули не значимы. Для каждого документа эталонный
   мультимножество чисел берётся из текстового слоя (для PDF) или задаётся вручную (для сканов,
   см. таблицу выше). Считаем precision / recall по числам.
2. **Арифметика.** Строка считается верной, если в ней выполняется `a × b ≈ c` (допуск 2 %) хотя
   бы для одной тройки чисел. Это не «фильтр», а разметка ролей колонок: количество, цена, сумма.
3. **Структура.** Число строк и колонок против истины (для сканов истина известна по картинке);
   шапка сверяется посимвольно с ожидаемой.
4. **Время.** Секунды на страницу, включая OCR и сборку; LLM-шаги в замер не входят.
5. **Цифры не поехали** (для квантования). Дополнительно считаем подстановки цифр: сколько чисел
   отличается от эталона заменой цифры (6↔8, 0↔6, 5↔3). Для финансов это отдельный вердикт.

Победитель — по числам и арифметике; время вторично. Правило проекта: меняем код только по замеру.

## 4. Требования к ONNX-детектору области таблицы (то, чего нам не хватает)

Нужен блок «найти, ГДЕ на странице таблица», чтобы structure-модель получала кроп, а не страницу.

- вход: та же PNG-страница 200 dpi; выход: список боксов `[x0,y0,x1,y1]` + score, опционально класс;
- обязательные случаи: (а) таблица с линиями, (б) таблица БЕЗ линий, (в) страница вообще без
  таблиц (ложные срабатывания недопустимы), (г) наклон/перспектива до ±10°;
- лицензия весов: Apache-2.0 или MIT (OpenRAIL-M и «доп. условия» не подходят для поставки);
- размер модели ≤ 50 МБ (лучше ≤ 20 МБ), CPU ≤ 1,5 с на страницу при 4 потоках;
- в поставке: файл ONNX, SHA256, opset, имена и формы входных/выходных тензоров, спецификация
  предобработки (resize/normalize/mean/std), источник и лицензия весов, 10 строк примера на
  `onnxruntime` без установки лишних пакетов.

Приёмка детектора: на 5 сканах с таблицами IoU бокса с истиной ≥ 0,5; на 5 страницах без таблиц —
ноль ложных срабатываний.

## 5. Требования к рецепту квантования (INT8)

- указать вид: dynamic quantization или QDQ; per-tensor или per-channel; какие слои исключить;
- если QDQ — предоставить калибровочный набор требований (сколько изображений, какого типа);
- ожидаемый эффект сформулировать в наших метриках: время на страницу и сохранность цифр
  (см. п. 3.5), а не «токены в секунду»;
- запрещено менять только ради скорости: если цифры «поехали» — рецепт отклоняется.

## 6. Формат отчёта о прогоне (его публикуем рядом с нашими цифрами)

```
модуль: <имя/версия>            документ: <файл>
страниц: N                      время: X с/страница (мин … макс)
числа: найдено K, эталон M → precision P, recall R
арифметика: верных строк V из W
структура: строк A против эталонных B, колонок C против D, шапка совпала: да/нет
цифры не поехали: да/нет (подстановок S)
вердикт: лучше/хуже нашего пути по числам и арифметике
```
