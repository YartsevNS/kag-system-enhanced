# Гид: выбор и смена embedding-модели

> Актуально на 2026-08-23. Проверять параметры моделей в админке/документации провайдера.

## Связка: embedding → Qdrant → Neo4j

- **Embedding-модель** превращает текст в вектор (список чисел). Задаёт **размерность** (dim) и **лимит входа**.
- **Qdrant** хранит векторы + текст чанков. Размерность коллекции = размерности модели.
- **Neo4j** хранит связи (Document → Chunk → Entity). Векторов там НЕТ — только текст-превью.
- **Чанкинг** делит документ на куски; размер чанка должен быть ≤ лимита входа модели.

## Модели GigaChat (официальная документация, июль 2026)

| Модель | Контекст | Размерность | Цена |
|---|---|---|---|
| `Embeddings` (текущая) | 512 токенов | 1024 | 14₽/1М |
| `Embeddings-2` | 512 токенов | 1024 | 14₽/1М |
| `GigaEmbeddings-3B-2025-09` | уточнять | уточнять | 14₽/1М |
| `EmbeddingsGigaR` | большой | уточнять | 14₽/1М |

Цена одинаковая — выбор по качеству/контексту.

## Наша текущая конфигурация (оптимальная)

- Модель: Embeddings (GigaChat), 1024 dim
- Лимит входа: ~500 символов (~350 токенов консервативно; реально 150-250)
- Чанк: 500 символов, overlap 15% (75)
- Qdrant: kag_documents, dense 1024, COSINE
- Почему 1024 хорошо: баланс точности/скорости/памяти; достаточно для русского нормативного текста; не избыточно (3072+ — 3× память без заметного прироста).

## Когда менять модель

- **Не менять** без причины — каждая смена с другой размерностью = пересоздание коллекции = потеря векторов.
- **Безопасный апгрейд:** Embeddings-2 (та же размерность 1024 → коллекция НЕ пересоздаётся, только переиндексация).
- **Осторожно:** EmbeddingsGigaR / 3B — возможно другая размерность → коллекция удалится и пересоздастся.

## Пошаговый алгоритм смены

1. Открой Админ → «Привязка функций» → функция `embedding`.
2. Выбери провайдера GigaChat + модель.
3. Сохрани — система проверит размерность тестовым запросом.
4. Проверь чанкинг: размер ≤ лимита новой модели (для 512-токеновых — 500).
5. Загрузи 1-2 тестовых документа, проверь поиск.
6. Нажми «♻️ Переиндексировать все документы» (время: ~1.5 мин/документ, 150+ = часы).
7. Дождись завершения (статусы на странице «Документы»).

## Последствия смены

### Сценарий А: та же размерность (Embeddings → Embeddings-2)
- Qdrant коллекция НЕ пересоздаётся; старые точки перезаписываются при переиндексации (force удаляет старые автоматически).
- Neo4j очищается и строится заново.
- Обязательна переиндексация.

### Сценарий Б: другая размерность
- Qdrant коллекция **удаляется и создаётся заново** — все векторы пропадают мгновенно.
- Все документы переиндексируются с нуля (несколько часов).
- Neo4j очищается и перестраивается.
- Если размерность ниже (384) — качество поиска может упасть.

### Что НЕ пострадает
Файлы, OCR-тексты, метаданные в PostgreSQL, история чата.

## Частые ошибки

1. chunk_size > лимита модели → хвост чанка не в векторе.
2. Смена модели без переиндексации → перемешанные результаты.
3. Переключение туда-сюда → многократное пересоздание коллекции.
4. overlap >25% → чанки-копии, лишняя стоимость.
5. Забыть лимит токенов → 413 (батч целиком).
