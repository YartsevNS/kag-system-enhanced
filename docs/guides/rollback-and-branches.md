# Ветки, точки отката и порядок работы (страховка перед экспериментом с OCR)

Дата: 27.09.2026. Причина: впереди замена OCR (PaddleOCR / PP-OCRv5 eslav вместо весов Occular). Эксперимент
может не оправдаться, поэтому рабочее состояние заморожено, и дальше работа идёт в отдельной ветке.

## Ветки

| Ветка | Назначение | Состояние |
|---|---|---|
| **PREPROD** | стабильная, основная на GitHub. **Не трогаем** — это путь отката | коммит `b2d3968`, метка `stable-occular-2026.09.27` |
| **TABLES** | дубль PREPROD (оставлен как был) | тот же коммит `b2d3968` |
| **paddle-ocr** | рабочая ветка эксперимента: PP-OCRv5 eslav через RapidOCR | начата от `b2d3968` |

Правило: вся новая работа идёт в `paddle-ocr`. В `PREPROD` вливаем только после того, как эксперимент пройдёт
приёмку (см. ниже). До этого `PREPROD` — рабочее состояние, которое можно вернуть одной командой.

## Что именно заморожено (состояние на 27.09.2026)

Функциональность замороженного состояния: текст и таблицы со сканов разбираются, таблица собирается своей сеткой
по линиям (объединённые ячейки, 27×19 на накладной), текст страницы собирается по порядку чтения, арифметика
таблиц проверяется (на накладной — «расхождений: 20 из 20»), просмотрщик показывает саму страницу скана,
таблицы со сканов в поиск НЕ идут (настройка `tables_in_fragments=false`).


## Откат на стенде 18 (без пересборки, самый быстрый)

Образы текущего состояния уже собраны и отправлены в Docker Hub, поэтому откат — это смена тегов в
`docker-compose.yml` и пересоздание контейнеров:

```bash
cd /home/yartsevn/kag-system
grep -n 'kag-api:\|kag-worker:' docker-compose.yml      # теги api/worker должны быть 2026.09.27.19
docker-compose up -d --force-recreate api worker worker-maintenance
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8000/api/v1/health    # ожидаем 200
```

Теги замороженного состояния: **api/worker `2026.09.27.19`**, база **`kag-base:2026.09.27.4`**.
Если образов нет локально — `docker pull kre44et/kag-api:2026.09.27.19` (они отправлены в хаб при выкатке).

## Как проверить, что откат действительно произошёл

1. `curl http://localhost:8000/api/v1/health` → 200; `docker ps | grep kag` → все контейнеры healthy.
2. Раздел «Таблицы документа» в просмотрщике отвечает: `/api/v1/upload/<id>/tables` → 200.
3. В журнале воркера после переобработки документа видны строки замороженного состояния:
   «текст страницы собран по порядку чтения», «восстановлено таблиц … (сетка по линиям: …)»,
   «арифметика таблицы 1: …».

## Приёмка эксперимента с новым OCR (когда можно вливать в PREPROD)

1. Тесты зелёные (в том числе чтение/арифметика/сетка).
2. Набор 30–50 страниц реальных УПД и накладных: доля строк, прошедших арифметику, выросла; контрольные числа
   совпадают с изображением.
3. Время на страницу не выросло критично (ориентир — текущие ~24 с на разбор таблицы накладной).
4. Лицензии чистые (PP-OCRv5 — Apache 2.0) — это, собственно, и цель замены.
