# Карточка документа: контекст эмбеддинга и точка level=document

Обновлено 2026-09-13. Модуль: `src/indexing/document_card.py`. Тесты: `tests/test_document_card.py` (21),
`tests/test_document_analyzer_parse.py` (8). Коммиты: `9cea61` → `3a58e4e`. Образ: `2026.09.13.56`.

## Зачем

Чанк «5.2.1 Требования к средствам защиты информации» без контекста почти неотличим от такого же
пункта другого документа. Классическое решение (Anthropic Contextual Retrieval) — LLM-вызов на КАЖДЫЙ
чанк: −35…−49 % неудачных поисков, но у нас это ~2 LLM-вызова на чанк, то есть на 2000 документов
сотни тысяч вызовов.

Мы делаем то же дешевле: документ и так анализируется одним вызовом
(`document_analyzer` → title/type/summary/topics). Префикс собирается ИЗ ГОТОВОЙ карточки —
**дополнительных LLM-вызовов нет**.

## Как работает

1. Анализ документа выполняется ДО векторизации (шаг 3а конвейера). Источник текста для карточки —
   `build_card_source(chunks)`: начало (титул, оглавление) + образцы середины и конца, ≤ 4000 символов.
   Раньше анализ шёл ПОСЛЕ векторизации и на эмбеддинг влиять не мог (первый чанк у ГОСТа — титул,
   по нему карточка выходила «Рекомендации по стандартизации» независимо от темы документа).
2. Префикс (≤ 200 символов): «название. тип. темы: …» попадает в metadata каждого чанка и
   добавляется к тексту ТОЛЬКО при индексации (passage). Запрос эмбеддится как есть —
   асимметрия query/passage. Заодно работает структурный префикс:

   `Р 1323565.1.004—2017. Рекомендации по стандартизации. темы: криптографическая защита… · п. 5.2.1: <текст>`

3. Точка документа (`level=document`, id = `uuid5('kag-doc-card:' + document_id)`) — карточка отдельным
   вектором. Поиск ФРАГМЕНТОВ её исключает (`must_not level=document`), новый
   `embeddings_service.search_documents()` ищет по карточкам — это основа сравнений
   («сравни требования в A и B») и вопросов «в каких документах есть X».
4. Права доступа карточки — те же поля, что у чанков (visibility/allow_*/deny_*): закрытый документ
   не должен «светиться» карточкой.

Настройки: `GRAPH_TRIAGE_ENABLED` (триаж, см. chunk-triage.md), длина префикса
`CARD_PREFIX_MAX_CHARS = 200`, объём источника `CARD_SOURCE_MAX_CHARS = 4000`.

## Ловушки (все найдены живой проверкой)

1. **Анализ документа не влиял на эмбеддинг** — он выполнялся после векторизации. Исправлено переносом
   шага до векторизации. Побочно: `record` (SQLAlchemy-объект конвейера) оставался со старыми полями,
   и в payload уходил `document_type="unknown"` — поля перечитываются из БД сразу после анализа.
2. **Поля анализа затирались финальным сохранением конвейера.** `_save_document_to_db` пишет из
   in-memory записи, загруженной ДО анализа; её пустые значения перетирали сохранённые
   `recognized_title/summary/topics/document_type`. Живой признак: **0 из 51 документа с названием**
   при том, что анализатор писал в лог «Метаданные обновлены». Теперь недостающие поля берутся из
   свежей записи БД.
3. **Анализатор молча возвращал {}**: одна попытка, а разбор JSON — регекспом `\{[^}]+\}`, который
   рвётся на markdown-обёртке и вложенных скобках. Следствие — пустые карточки. Теперь:
   `_extract_json` (снятие ``` в любом месте + сбалансированный `raw_decode`), две попытки, во второй —
   явное требование только-JSON и `max_tokens` 500 (обрыв ответа = невалидный JSON), причина отказа в логе.
4. **Карточка попадала в выдачу чата.** Фильтр поиска собирался только внутри `if conditions:` —
   исключение карточек (и ACL-запреты!) не применялось, когда условий не было. Теперь `must_not`
   строится всегда.
5. **`qdrant.set_payload` не существует** у `QdrantService`: обновление payload в анализаторе падало
   в `DEBUG` с самого начала — `document_type/summary/topics` в payload чанков не попадали никогда.
   Добавлен `embeddings_service.update_document_payload()` (set_payload по фильтру document_id,
   sync-клиент в `to_thread`, ошибка → warning).
6. **Имя не в области видимости** (второй раз за сессию): `get_doc_repo` в `document_service`
   импортируется ЛОКАЛЬНО внутри функций, поэтому новый блок карточки падал `NameError`, а fail-open
   сообщал «карточка не собрана». Правило: после вставки кода в существующий модуль грепнуть, что все
   вызываемые хелперы в нём импортированы (для новых имён Python не выдаёт ошибку до запуска).

3. Поиск: карточек среди фрагментов 0; `search_documents` отдаёт карточки.
4. Eval до/после переиндексации на наборе `scripts/eval_questions.json` — единственный честный
   показатель «стало ли умнее», а не «фича включилась».
