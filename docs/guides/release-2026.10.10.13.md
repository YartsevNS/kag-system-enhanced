# Релиз 2026.10.10.13 — что вошло и как выкатывался

Ветка: `feature/encoding-fix-and-graph-ontology`, последний коммит `dcc1ca6`.

## Что в релизе (по задачам, с причинами)

**Русский в конвейере (дефект, жил месяцами).** Текстовые файлы (.txt/.md/.csv) обрабатывались общим
путём «PyMuPDF → распознавание как картинка»: байты текста уходили службе распознавания вместо
изображения, и она возвращала мусор. Так 29 документов (1959 фрагментов) получили текст, прочитанный
как Latin-1. Причина устранена: кодировку решает единый модуль `src/indexing/text_encoding.py`
(порядок кодировок, проверка доли кириллицы, восстановление обоих направлений порчи, признак
`encoding_suspect` в метаданные), текстовые расширения больше не идут в распознавание.

**Онтология связей.** `src/indexing/graph_ontology.py`: 13 осмысленных типов с допустимыми парами,
канонизация свободных названий, проверка тройки перед записью, правила для задания модели. Было:
проходили схему 27%, нарушали 16,6%, 56% свалено в мусорку `BELONGS_TO`. Стало (подмножество
кибербез+юристы): проходят 50,7%, нарушают 1,7%.

**Типы сущностей правилами.** `src/indexing/entity_typing.py`: номера ГОСТ → `standard`, «А.1.1»/«п. 4.4»
→ `clause`, реквизиты актов и номера законов → `document_ref`, даты → `date`; неопознанное не меняется.

**Слой правил в графе.** `scripts/bakeoff/build_skeleton.py`: узлы стандартов и пунктов, связи
«документ ссылается на стандарт», «содержит пункт», «фрагмент упоминает», происхождение `layer=regex`.
На подмножестве: 84 узла стандартов, 337 узлов пунктов; «ГОСТ Р 34.11» указан в 30 документах.

**Скорость.** Таймаут обращения к модели 180 → 20 с (`GRAPH_LLM_TIMEOUT`); конкурентность общая на
процесс (`GRAPH_LLM_CONCURRENCY`, было на документ); таймаут фрагмента 60 → 120 с
(`GRAPH_CHUNK_TIMEOUT` — при 60 с фрагменты пропускались, а это потерянные факты); структурный вывод
JSON с откатом (`GRAPH_JSON_MODE`).

**Происхождение и канонизация.** У каждой связи пишется `layer` (model/regex) вместе с версиями схемы
и извлекателя — связь без происхождения в граф не попадает. Названия канонизируются по одобренному
словарю алиасов в момент извлечения, а не только постфактум.

## Как выкатывался

1. Сборочное дерево: `/home/yartsevn/kag-build-enc` (worktree). Обновление:
   `git fetch origin feature/encoding-fix-and-graph-ontology && git reset --hard origin/<ветка>`.
   **Грабля:** `FETCH_HEAD` в worktree свой — после `fetch` из основного дерева он не виден, а
   `git checkout --detach FETCH_HEAD` в этой версии git не принимает аргумент. Использовать
   `reset --hard origin/<ветка>`.
2. Сборка (база не пересобиралась — новых зависимостей нет, модули на stdlib):
   `docker build -q -t kre44et/kag-api:2026.10.10.13 -f Dockerfile .`
   `docker build -q -t kre44et/kag-worker:2026.10.10.13 -f Dockerfile.worker .`
3. Теги в `docker-compose.yml` (api и worker ×2 — образ воркера обслуживает и worker, и
   worker-maintenance): `.11`/`.9` → `.13`. Резервная копия компоуза сделана перед правкой.
4. `docker-compose up -d --force-recreate api worker worker-maintenance`.
5. Выгрузка в реестр: `docker push` для обоих образов.
