# Обработка документов: загрузка без автозапуска + блокировка

Фича (2026-08-28): загрузка документа через API/UI создаёт файл и миниатюру,
но НЕ запускает обработку автоматически. Обработка (OCR → чанки → векторы → граф)
запускается только кнопкой «Обработать» на странице «Документы»
(POST /api/v1/upload/{id}/process).

## Поведение

1. **Загрузка** (POST /api/v1/upload, /batch, /bulk, TUS) — документ сохраняется,
   статус `pending`, в Celery НЕ ставится. Обработка отложена.
2. **Общая кнопка «Обработать все необработанные»** — под панелью
   «Права доступа к документам» на странице «Документы» (видна, если есть
   необработанные документы пользователя). Ставит в очередь ВСЕ свои
   документы со статусом `pending`/`failed` одним нажатием.
3. **Многопользовательность** — process/process-all обрабатывают ТОЛЬКО
   документы текущего пользователя (`uploaded_by == id`); админ — любые,
   системные документы без владельца — только админу/процедурой web_monitor.
   Чужой пользователь получает **403**
   «Недостаточно прав: можно запускать обработку только своих документов».
4. **Блокировка из админки** (секция «Обработка документов»):
   - `config_store` → `system`/`processing` = `{blocked: bool, message: str}`
   - При `blocked=true`:
     - кнопка «Обработать» disabled (с подсказкой);
     - POST /{id}/process → **423** «Обработка заблокирована администратором...»;
     - POST /reprocess-pending → **423**;
     - на странице «Документы» показывается жёлтый баннер:
       «Обработка после загрузки может не начаться — в связи с блокировкой
       на техническое обслуживание. Обратитесь к администратору.»

## Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| GET | /api/v1/admin/models/processing-config | {blocked, message} |
| POST | /api/v1/admin/models/processing-config | сохранить блокировку (admin) |
| POST | /api/v1/upload/{id}/process | запустить обработку одного документа (403 чужому, 423 при блокировке) |
| POST | /api/v1/upload/process-all | обработать ВСЕ необработанные документы текущего пользователя (423 при блокировке) |

## Файлы

- `src/api/routes/upload.py` — убран автозапуск enqueue (4 места), добавлен
  `process_document_now`, блокировка в `reprocess_pending_documents`
- `src/api/routes/admin_models.py` — GET/POST `processing-config`
- `src/api/static/documents.html` — баннер, кнопка «Обработать», loadProcessingConfig/processDocument
- `src/api/static/admin.html` — секция «Обработка документов» (сворачиваемая)

## Примечания

- Внутренние загрузки (web_monitor → document_service напрямую) НЕ затронуты:
  они обрабатывают сразу, минуя API.
- Админские инструменты (reindex, reprocess-ocr) блокировкой НЕ ограничены —
  блокировка только для пользовательского запуска со страницы «Документы».
