# Что меняется как: настройки, код, образ

Правило проекта: **пересборка образа — последнее средство, а не первое.** Прежде чем собирать
новый тег, определить уровень изменения по таблице ниже.

## Три уровня изменений

| Что меняем | Что требуется | Сколько времени | Где живёт |
|---|---|---|---|
| Значение настройки (порог, модель, чанкинг, глубина поиска) | ничего, обновится само | до 30 с (кэш) | Postgres, `config_store` |
| Текст промпта извлечения | ничего, действует со следующего прогона | 0 | Postgres, таблица `ontology_prompts` |
| Схема онтологии TypeDB | ничего, применяется через редактор | 0 | TypeDB, база `cybersecurity_ontology_v2` |
| Имя базы / адрес TypeDB, пароли, порты | `docker restart kag-api` | 3 с | `.env`, монтируется в контейнер |
| HTML, JS, CSS страниц | ничего (в режиме отладки) | 0 | `src/api/static`, монтируется |
| Python-код (`src/**/*.py`) | `docker restart kag-api` (в режиме отладки) | 3 с | `src`, монтируется |
| Зависимости (`requirements.txt`), веса моделей, `Dockerfile` | сборка образа | 2–5 мин | внутри образа |

## Режим отладки на сервере 192.168.50.18

Образ фиксированный, код монтируется с диска через `docker-compose.dev.yml`.

    # постоянная рабочая копия на ветке work — держать только для монтирования
    cd /home/yartsevn/kag-system
    git worktree add /home/yartsevn/kag-live work      # один раз

    # запуск с монтированием кода
    cd /home/yartsevn/kag-live
    KAG_ROOT=/home/yartsevn/kag-system \
    docker-compose -f /home/yartsevn/kag-system/docker-compose.yml \
                   -f ./docker-compose.dev.yml up -d api worker

    # после правки Python-файла
    docker restart kag-api

    # после правки HTML — ничего не делать, страницы отдаются с no-store

## Когда сборка всё-таки нужна

1. Изменён `requirements.txt`, `Dockerfile`, `Dockerfile.worker`.
2. Обновились веса моделей или базовый образ `kag-base`.
3. Готовится поставка заказчику: артефакт — образ, поэтому в него попадает только
   зафиксированный коммит, а не рабочий каталог.
4. Код должен работать без монтирования (проверка «как у заказчика»).

## Почему так, а не «просто rebuild каждый раз»

- Сборка образа на 2–3 минуты при каждой правке страницы — это 20–30 минут в день на ожидание.
- Монтирование не отменяет образ: контейнер остаётся постоянным, меняется только источник кода.
- Риск режима отладки — расхождение «на диске» и «в образе». Поэтому перед приёмкой
  и перед поставкой обязательна проверка из чистого образа (без `docker-compose.dev.yml`).

## Что уже вынесено из образа

| Часть | Где живёт | Меняется без перезапуска |
|---|---|---|
| настройки поиска, OCR, моделей | Postgres `config_store` | да |
| промпты извлечения | Postgres `ontology_prompts` | да |
| схема онтологии | TypeDB | да |
| очередь предложений онтологии | Postgres `ontology_proposals` | да |
| словари видов и тем | Postgres, админка `/semantics` | да |
| страницы интерфейса | `src/api/static` (в отладке — с диска) | да |
| Python-код | `src` (в отладке — с диска) | перезапуск |

## Проверка режима отладки

```bash
# 1. код в контейнере — с диска, а не из образа
docker exec kag-api sh -c 'grep -c "<маркер>" /app/src/api/static/<страница>.html'
# на хосте и в контейнере число совпадает

# 2. правка страницы видна без перезапуска
curl -s http://localhost:8000/static/<страница>.html | grep -c "<маркер>"

# 3. правка Python-кода видна после перезапуска
docker restart kag-api && sleep 8 && curl -s -o /dev/null -w '%{http_code}\n' \
  http://localhost:8000/api/v1/health
```
