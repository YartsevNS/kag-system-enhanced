## Чего не хватает

1. **Строчного слоя в Postgres** — есть только таблица целиком. Нет фильтров и вычислений.
2. **Таблиц как самостоятельных векторов** — строки не индексируются, в разметке нет `table_id`
   и типа фрагмента, при склейке сегментов границы таблицы теряются.
3. **Маршрутизатора вопроса** — смысловой поиск / точный поиск / вычисление.
4. **Оценки качества извлечения** и второго экстрактора (pdfplumber, Camelot): криво разобранную
   таблицу сейчас нечем заметить и нечем подменить. Нет нормализации (шапка не всегда первая
   строка, «15400,50» не превращается в число с сохранением оригинала).
5. **XLSX/CSV** заводятся как текст, а не как структурированные строки (проверить и решить).

## Этапы

**Этап 1. Каркас разметки.** ✅ СДЕЛАНО (коммит b99014a): устойчивый `table_id`
(uuid5 документ+страница+сквозной номер), оценка качества извлечения, таблица — отдельным
чанком (не склеивается с текстом и соседней таблицей), табличные поля в payload Qdrant,
колонки `table_id/row_count/quality` в `document_tables`. Тесты — 21.

**Этап 2. Строчный слой.** ✅ СДЕЛАНО (коммит a52ae45): таблица `table_rows` (оригинал
ячеек + распознанные числа + текст строки), сохранение при обработке и по уже загруженным
документам (`scripts/backfill_table_rows.py`, есть `--dry-run`), безопасные запросы по
плану: белый список операций и агрегатов, проверка колонок по заголовкам таблицы, значения
параметрами, лимит и время. Тесты — 29.

**Этап 4. Вычисления в чате (SQL).** ✅ СДЕЛАНО (коммит в тот же заход): маршрутизатор
`src/indexing/table_router.py` — канонические роли колонок со словарём синонимов
(«на какую сумму» → «Цена, руб.»), определение вычисления и фильтров, выбор таблицы по
покрытию ролей и по документам из результатов поиска, план → запрос → ТЕКСТ ОТВЕТА со
ссылкой на документ, страницу и таблицу. Четыре исхода не смешиваются: посчитано /
ноль по условию / нет подходящей колонки / вопрос не про вычисление. Отдельно
предупреждаем, когда часть значений не распознана как число (сумма занижена).
В чате блок подключается после поиска и графа, синхронные запросы уходят в отдельный поток,
включается настройкой `sql_enabled`. Тесты — 23.

**Этап 3. Векторы таблиц (сводка/строки/группы).** НЕ СДЕЛАНО. Порядок работ по итогам
консультации: сначала «карточка таблицы» (заголовки, роли, примеры строк, число строк,
страница) — по ней выбирать таблицу, затем строковые векторы с ограничителями
(`max_rows_for_row_vectors`, `min_quality_for_rows`). Нужен замер: сколько времени
добавляет эмбеддинг на каждую строку и что это даёт по качеству.

**Этап 5. Качество извлечения и второй экстрактор.** НЕ СДЕЛАНО: pdfplumber включается
только при низком качестве PyMuPDF, нормализация значений (числа с сохранением оригинала
уже есть в строчном слое), объединённые ячейки, Camelot выключен по умолчанию.

**Этап 6 (по желанию).** XLSX/CSV как полноценные источники; снимок области таблицы со
страницы, чтобы открывать исходный фрагмент.

## Что сказал консультант (Polza, deepseek-v4.1-flash; полные ответы в reports/_scratch/consult_sql*.md)

- Модель НЕ должна писать SQL: только структурный план, SQL собирает код — иначе на русских
  формулировках путаются «цена/стоимость/сумма» и выдумываются колонки. Совпадает с тем, что
  сделано.
- Канонические роли колонок + словарь синонимов + нормализация заголовков (без единиц
  измерения) — сделано.
- Правило «на какую сумму»: сначала колонка суммы, иначе считать price×quantity — вторая
  часть пока НЕ реализована (нужна поддержка выражений из двух колонок), сейчас честно
  говорим, что колонки для суммы нет.
- Выбор таблицы: «карточка таблицы» в Qdrant + гибридный поиск (фильтры по документу,
  BM25 по заголовкам, вектор по карточке, реранк) — это этап 3. Не смешивать документы
  молча: если таблица из документа вне результатов поиска — не брать.
- Предупреждения о качестве цифры (не распознанные числа, строки-итоги «Итого/Всего»,
  разные единицы в одной колонке) — часть реализована (не распознанные числа), остальное
  в бэклоге этапа 5.

## Замер

Пока в наборе из 20 вопросов нет вопросов про таблицы. До этапа 3 нужно собрать 10–15
вопросов по реальным документам с таблицами и эталонными ответами, включая:
вычисление суммы, фильтр по числу, вхождение названия, вопрос без данных в таблицах
(проверка «не соврал»). База по текущему набору: 0.7722 (глубина контекста 10, без пометки).

## Правила работы

- Эталон не трогаем: всё — в `TABLES`, образы — своей серией тегов (2026.10.*).
- Каждый этап: тесты + живая проверка на стенде + замер, затем отчёт.
- Новые настройки табличного стека — в `config_store` (namespace `tables`), чтобы включать и
  выключать дорогие части без пересборки образа.
