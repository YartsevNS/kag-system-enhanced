## Чего не хватает

1. **Строчного слоя в Postgres** — есть только таблица целиком. Нет фильтров и вычислений.
2. **Таблиц как самостоятельных векторов** — строки не индексируются, в разметке нет `table_id`
   и типа фрагмента, при склейке сегментов границы таблицы теряются.
3. **Маршрутизатора вопроса** — смысловой поиск / точный поиск / вычисление.
4. **Оценки качества извлечения** и второго экстрактора (pdfplumber, Camelot): криво разобранную
   таблицу сейчас нечем заметить и нечем подменить. Нет нормализации (шапка не всегда первая
   строка, «15400,50» не превращается в число с сохранением оригинала).
5. **XLSX/CSV** заводятся как текст, а не как структурированные строки (проверить и решить).

## Этапы

**Этап 1. Каркас разметки.** Таблица получает `table_id`; в Qdrant появляются табличные поля
(`table_id`, `chunk_type`, `row_index`, `columns`, `page`, `table_index`). Поведение не меняем.
Обязателен независимо от решения по SQL.

**Этап 2. Строчный слой.** Таблица строк в Postgres: строка как JSON + текст строки
(«Наименование: Насос НЦ-50; Количество: 12»). Скрипт заполнения для уже загруженных документов,
сверка количества строк с `rows_json`.

**Этап 3. Векторы по уровням.** Сводка таблицы, строка, группы строк (10–30) с табличными полями
в разметке, индексы по `document_id`, `table_id`, `page`, `chunk_type`. Это чинит вопросы
«какая цена у X», «какие позиции дороже 10 000».

**Этап 4. Маршрутизатор (вычисления).** Классификация вопроса; для расчётов — SQL по строчной
таблице: только чтение, шаблоны запросов по распознанным колонкам (модель НЕ пишет свободный SQL),
лимит строк и таймаут; ответ со ссылкой на документ, страницу и таблицу. При любой неуверенности —
откат на текущий путь. РЕШЕНИЕ ПОЛЬЗОВАТЕЛЯ ЕЩЁ НЕ ПОЛУЧЕНО.

**Этап 5. Качество извлечения.** pdfplumber как второй экстрактор с профилями «по линиям» и
«по тексту», оценка качества таблицы, нормализация (шапка, числа с сохранением оригинала,
объединённые ячейки), Camelot третьим запасным (тянет ghostscript/opencv — только если оправдается).

**Этап 6 (по желанию).** XLSX/CSV как полноценные источники; снимок области таблицы со страницы,
чтобы открывать исходный фрагмент.

## Замер

Пока в наборе из 20 вопросов нет вопросов про таблицы. До начала этапов 2–4 нужно собрать
10–15 вопросов по реальным документам с таблицами и эталонными ответами — иначе улучшение нечем
доказать. База по текущему набору: 0.7722 (глубина контекста 10, без пометки лучшего фрагмента).

## Правила работы

- Эталон не трогаем: всё — в `TABLES`, образы — своей серией тегов (2026.10.*).
- Каждый этап: тесты + живая проверка на стенде + замер, затем отчёт.
- Сначала выравниваем поведение (этап 1) и только потом меняем качество поиска.
