# Источник и метаданные документа при загрузке, 07.11.2026

Требование владельца: при загрузке через сайт обязательно выбрать «Компания» или «Регулятор»;
плюс уточняющие метаданные — регулятор (ФСТЭК России, Росстандарт…) и тип документа
(ГОСТ, стандарт, политика, инструкция). Значения можно вписать свои, справочники — подсказки.

## Что реализовано

    documents.source_kind      company | regulator (миграция: 37 regulator, 134 пусто)
    source_metadata            JSON: source_kind, issuer, doc_kind (+ source_name/source_url)

Обязательность при загрузке через сайт (`/upload/`, `/batch`, `/bulk`, `/import-folder`):

    без source_kind      → 400 SOURCE_KIND_REQUIRED
    без doc_kind         → 400 DOC_KIND_REQUIRED
    regulator без issuer → 400 ISSUER_REQUIRED

Проверено запросом без полей: ответ `{"code":"SOURCE_KIND_REQUIRED", ...}`.

## Онтология

`typedb_writer` для `source_kind=company` переклассифицирует `regulatory_document` в
`company_document` (title + version_string), связь `document_issuance` не ставится.
Для регулятора — как было.

Сквозная проверка на тестовой политике ООО «Ромашка» (2 чанка, `0f1d7cc6`):

    до фикса    regulatory_document: 1   (воркер терял source_kind)
    после фикса company_document: «Политика информационной безопасности»,
                 «45 Политика информационной безопасности ООО «Ромашка»»,
                 structural_element 17, security_measure 3 (3.1, 3.2, 3.3), cii_object 2

Причина первого провала: `src/indexing/tasks.py` пересобирал `DocumentRecord` из БД без
`source_kind`, `collection`, `source_metadata`. Исправлено, тест `test_worker_keeps_source_metadata`.

                      Правительство РФ, Президент РФ, Роскомнадзор, Минобороны

                      положение, методический документ, рекомендации, регламент
    тип (компания)    политика, инструкция, приказ, положение, регламент,
                      стандарт организации, модель угроз, акт, предписание

Поле — `input` + `datalist`: список подсказывает, но принимает любое значение.
